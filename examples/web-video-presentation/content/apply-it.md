## 骨架模式

把 web-video-presentation 的十三张卡压成一个可搬走的原型，它是一条**节拍驱动的批量演绎流水线**：

```text
内容定稿（带机器可验下限）
  → 一次全量对齐（所有作废型决策收进一个检查点）
  → 锚点验收（第一件产品串行做完整、过人审）
  → 受控批量（共享只读资源兜底 + 物理隔离 + 差异定性）
  → 单源驱动交付（多消费方的数字只存一份）
```

这条公式的不变量，比公式本身更重要：

- **内容先于形式。** 形式层（视觉、动画、排版）永远不许反过来裁剪内容层——所以保留度下限（A3）在流水线最前端。
- **计划写 what，不写 how。** 上游钉死改起来贵的决策（内容、节奏），把需要现场上下文的决策（视觉、措辞）留白给下游（A2）。
- **返工经济学决定检查点位置。** 检查点不是越多越好，是恰好卡在「错误开始指数放大」之前（A6、A7）。
- **一致性不靠叮嘱，靠资源。** 并行体必须一致的部分沉到共享只读层，可以不同的部分明文定性为特性（A8）。
- **多消费方的真相只存一份。** 宁可改设计消灭副本，不写校验脚本对账（A1）。
- **查 → 修 → 报，顺序不可换。** 用户看到的永远是修复后的版本＋自检证据（A10）。

## 新场景

你的播客做了 40 期，每期 60~90 分钟，有完整的转写稿。现在要做一个 skill：把每期节目转成一篇「图文精华帖」——正文带小标题和拉引（pull-quote），关键观点配时间戳跳转链接，每篇文末有金句卡片图。要批量生产 40 篇，质量要稳定，而且你只想全程确认两三次，不想 40 篇逐篇盯。

棘手的地方和做视频惊人地像：转写稿 8000 字，AI 一定想「精炼」成 1500 字；40 篇并行生产，风格会散；时间戳、拉引、金句卡这三处都引用原文，错一处读者点过去对不上；金句卡片图的视觉风格还得统一。

## 任务

- 列出这个任务里「AI 默认会做坏」的三件事，每件写成可观察的症状（参照 A3、A5、A10 的症状写法）
- 从档案里挑 4~6 张卡，说明每张在这个场景里的对应物是什么（比如：narrations.ts 的对应物是什么文件？）
- 画出你的流水线：阶段、检查点位置、每个检查点对齐哪几件事
- 写出你的「唯一真相源」设计：时间戳、拉引、金句三个消费方共用什么账本？
- 给「精华帖」定一个机器可验的内容下限（A3 的 60% 直接抄能用吗？为什么？）
- 写出迷你 skill 的入口文件骨架：阶段标题＋每阶段一句话＋必读文件表

## 参考答案

先看症状（你的版本不必一样，但必须可观察）：

- 摘要化：8000 字转写稿出来 1200 字，嘉宾最精彩的反直觉观点（「涨粉最快的那期是我最不想发的」）被删——因为它和主题「不搭」。
- 风格散：40 篇并行，有的用「家人们」开头、有的用学术腔，金句卡一半圆角粉渐变一半黑白。
- 引用漂移：正文改了一轮后拉引没跟着改，时间戳还指着旧段落——读者点过去听到的不是引文那句话。

卡片映射（一种合理的挑法）：

| 档案卡 | 在播客场景的对应物 |
| --- | --- |
| A3 保留度下限 | 精华帖 ≥ 转写稿信息量的某个下限——但 60% 字符比**不能直接抄**：转写稿有大量口水词，合理做法是先机器去口水（嗯、呃、重复），再对「观点条目数」立保留下限（每期先抽观点清单，帖子必须覆盖 ≥ 80% 条目） |
| A1 唯一真相源 | 每期一个 `quotes.json`：每条引用＝{时间戳, 原文, 用途}；正文拉引、时间戳链接、金句卡全部从它取，谁都不许手写引文 |
| A2 计划留白 | 每期的「结构稿」只定小标题和观点分配，不定措辞和拉引位置——措辞留给成文时看上下文定 |
| A6 一次对齐 | 第 1 个检查点：栏目模板＋视觉主题＋发布平台＋批量模式，四件事一次定 |
| A7 锚点验收 | 第 1 篇串行做完整（含金句卡成图），人审通过后才开批量 |
| A8 并行隔离 | 每期独立目录；语气和卡片样式锁进「栏目 token」（称呼、口头禅黑名单、卡片模板）；篇间风格差异定性为「每期嘉宾的气质」 |

流水线（两个检查点，对齐两次＋锚点验收一次，满足「只确认两三次」）：

```text
Phase 1  逐期产出观点清单 + quotes.json（机器验：观点覆盖率 ≥ 80%）
   ▼ ◆ Checkpoint：模板 / 视觉 / 平台 / 批量模式，一次对齐
Phase 2  第 1 篇完整成文 + 金句卡成图 → 人审锚点
   ▼
Phase 3  第 2~40 篇并行（栏目 token 兜底；每篇完工自检→修复→交付）
   ▼ ◆ Checkpoint：抽查 3 篇 + 发布节奏确认
Phase 4  批量发布
```

入口文件骨架（节选）：

```markdown
# Podcast Digest Skill

## Phase 1 观点清单 + quotes.json
读 references/EXTRACT-RULES.md。转写稿 → 观点清单（逐条带时间戳）。
机器验：观点覆盖率、quotes.json schema。

## Checkpoint：一次对齐 4 件事
模板 / 视觉 / 平台 / 模式。视觉必须明确才进 Phase 2。

## Phase 2 第 1 篇 = 锚点（×1，主线程）
## Phase 3 第 2~40 篇（×39，每篇必读 references/POST-CRAFT.md）
完工自检 → 先修复 → 再交付。引文一律从 quotes.json 取。
```

对照一下你写的版本：检查点是不是卡在批量开始之前？真相源是不是让「手写引文」无处可写？下限是不是机器可验？三个都是，骨架就立住了。
