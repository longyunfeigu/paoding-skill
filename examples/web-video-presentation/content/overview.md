## 开场

你对 AI 说：「这是我公众号那篇《我让 5 个 AI 工具重写我的博客》，帮我做成 B 站视频。」

十分钟后它交货了：一个单页 React 站，渐变大标题，五个工具整整齐齐排成卡片列表，底部还有版权栏。看起来挺像回事。

你打开录屏软件，准备照着稿子念。第一个问题来了：页面是上下滚动的。你一边念一边滚，滚轮每动一下，画面跳一截——这录出来不是视频，是网页浏览实录。

你凑合录完第一段，发现第二个问题：你口播刚讲到第二个工具，画面上五个工具早就全亮着。观众的眼睛比你的嘴快，你还在讲 Cursor，他已经把第五个看完了。

你回头让 AI 改成「点一下出一个」。它改了。然后你想配个音、让页面自动播。这时第三个问题浮出来：稿子切了 36 段，页面做了 41 步，音频合成了 38 个文件——三个数字对不上，没有任何人知道哪个是对的。

还有一个更早埋下的问题。AI 把你 2000 字的文章「改写成口播稿」时，顺手删掉了两个案例和所有反方观点，又加了一句开场白：「我知道你最近肯定在纠结选哪个 AI 工具」。这句话你念出来试试——一股推销味，真人不会这么开口。

换一个会写 React 的工程师来做，死法不同但也会死：他第一反应是做响应式布局——这是网页开发十年的肌肉记忆。可录屏要的是反的：一个永远不变形的固定坐标系。

把这几个坑摆在一起看就清楚了：**「做个好看的网页」和「做一个能录成视频的网页」是两个任务。**后者的每一个约束——固定画幅、节拍驱动、口播画面同步——都和默认网页开发的直觉对着干。

这个 skill 就是冲着这条沟来的。它的办法不是「写更好的网页 prompt」，而是把整件事改成一条流水线：先把稿子和节奏钉死，停下来跟你对齐五件事，然后才许写代码——而且第一章写完必须等你验收。

## Primer

先把几个概念用大白话说清楚，再看全景。

**产出物是什么。** 一个 Vite + React 项目，运行起来是一个 16:9 的「舞台」：内容固定画在 1920×1080 的坐标系上，整体缩放适配屏幕，没有响应式断点。每次点击推进一步，每一步独占整屏。进度条平时隐形，鼠标悬到底边才出现——录屏画面里没有任何网页痕迹。录下来，就是视频。

**step（节拍）。** 口播里一个聚焦的想法，就是一个 step：点一下，讲一件事。口播稿用 `---` 把想法切开，每段对应一次点击。这个对应关系是整条流水线的龙骨——后面所有文件都围着它转。

**章节 × step。** 整片视频切成 N 章（开场钩子、五强登场、实测对比……），每章是一个独立文件夹里的 React 组件，组件是 step 的纯函数：`if (step === 2) return <某一屏/>`。没有定时器，没有内部状态——给定 step，画面唯一确定，录屏可以随时重来。

**双源原则。** 节奏跟口播稿走，画面细节回原文章抽。口播说「Cursor 翻车了两篇」，画面上还挂着原文里的具体数字「改写 7 篇、2 篇要返工」——口播负责讲清楚，画面负责比口播更密。原文 article.md 全程保留不删，就是为了随时回去抽细节。

**主题 token。** 颜色和字体不许写死，必须走语义 token（`--accent`、`--font-display-cn`……）。skill 内置 10 套主题，每套一个 tokens.css——换主题等于覆盖一个文件，章节代码一行不动。字号、间距、动画时长倒是随便写：那些是每章的创作自由。

**narrations.ts。** 每章有一个 narrations.ts 文件：一个字符串数组，长度就是这章的 step 数，每个元素就是这一步要念的口播。音频按它逐条合成 mp3——step 数和口播文本，全工程只有这一个出处。

**Auto 模式。** 三种播放模式里的全自动档：URL 加 `?auto=1`，每进一步自动播这一步的 mp3，播完自动翻页——录屏一镜到底，音视频天然同步。

**协作节奏。** 流水线上有两个必须停下来的检查点（写代码前对齐五件事；烧钱合成音频前确认文本），外加一个硬验收：第 1 章必须做完整、让用户点头，才许继续往下做。

把这些串起来：**稿子和计划 → 对齐 → 脚手架 → 第 1 章锚点 → 批量开发 → 音频 → 录屏**。下面的全景图就是这条线。

## 难点预览

### 计划写得越细，成片越像模板

**坑:** outline 里把每步动画都安排得明明白白，看着特别专业——成片出来，38 步全是同一种淡入。计划越细，视频越像罐头。
**最值得学的一招:** outline 有一张「必须写 / 不要写」边界表：屏幕内容、step 数、信息池必须写，动画类型、CSS 手段、时长数值禁止写——把视觉决策留到章节实现时按内容即时设计。
**维度:** 领域-认知
**深入:** stage-01 · A2

### step 数散落五处，必然漂移

**坑:** 稿子切了 36 段、页面写了 41 步、音频合成 38 个 mp3——录到中段，口播和画面错位，整片对不上嘴。
**最值得学的一招:** 每章一个 narrations.ts 数组当唯一真相源：数组长度＝step 数，数组元素＝音频文本；注册表连 totalSteps 字段都不存在，想漂移都没有地方写。
**维度:** 领域-认知
**深入:** stage-06 · A1

### 形式全改对了，念出来还是机器

**坑:** 自检清单全绿的稿子，第一句就让人起鸡皮疙瘩——观众三秒划走，而清单查不出原因。
**最值得学的一招:** 自检分三层，最后一层是「张嘴念出来」：随便挑三段真的念，哪句说不出口哪句就是 AI 味——这是机器查不了、必须执行的体检。
**维度:** 品味
**深入:** stage-01 · A4

### 并行开发，风格统一是个伪目标

**坑:** 想让并行的几个 subagent 「保持风格一致」——可它们互相看不见对方的产出，机械对齐根本不可能，结果要么互改共享文件打架，要么色板字体各跑各的。
**最值得学的一招:** 不追求一致，改求兜底：颜色字体锁死在主题 token 里，每章独立文件夹独立 CSS 前缀，注册表谁都不许动——气质不会跑偏，剩下的差异被明文定义为「人手写视频的呼吸感」。
**维度:** 编排
**深入:** stage-05 · A8

### 动画长了，录屏时被当场切断

**坑:** 某步做了 6 秒的精彩动画，口播只有 3 秒——自动录屏严格按音频结束翻页，动画演到一半被切。
**最值得学的一招:** 作者删掉了曾经存在的「最少停留时间」旋钮（代码注释原话：intentionally no minimum hold knob），把规则收成一条死的：动画时长 ≤ 口播时长，不够就加口播、拆 step 或加速动画。
**维度:** 领域-工程
**深入:** stage-05 · A9

## 章节逻辑

- 实战走查｜跟着 agent 把「5 个 AI 工具测评」这一单从头做到尾，七站每站看：默认会怎么坏、skill 怎么防、真实产出长什么样
- 中间产物与数据流｜换一个视角沿数据走：article.md 到成片之间每个文件谁写谁读、为什么长这样
- 难点档案｜把走查里见过的难点做成 12 张可检索的卡片，外加诚实的残渣清单和盲区
- 迁移练习｜给你一个新场景（播客转视频课），练习挑卡片、拼出自己的迷你 skill 骨架
- 术语表｜6 个贯穿全书的词，查阅用，不在主线上
- 带走工具箱｜正文里所有标了「📌 可带走」的通用招自动汇总在这里——赶时间的人直接从这页挑
