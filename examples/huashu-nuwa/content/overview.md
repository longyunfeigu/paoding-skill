## 开场

你把这句话丢给一个没装任何 skill 的 agent：「帮我做一个乔布斯的思维 skill」。

它几秒钟就开始写了。

标题《史蒂夫·乔布斯思维精华》，然后是「Stay hungry, stay foolish」「活着就是为了改变世界」「专注就是说不」，一条一条，排得很整齐。

读起来挺像那么回事。金句都对，语气也热血。

然后你试着用它。你问：「我在做一个折叠屏手机，乔布斯会怎么看？」

它回你一段话：要专注、要极致、要关注用户体验、不要为了技术而技术。每个字都对，但你换成「马斯克会怎么看」「随便哪个产品经理会怎么看」，答案几乎一样。

你又问：「乔布斯会怎么评价 Vision Pro？」

它张口就来——讲得头头是道，引用了几个「乔布斯说过」的观点。可乔布斯 2011 年就走了，Vision Pro 是 2024 年的产品。它在用旧记忆编一个听起来像乔布斯的人。

问题不在于它写得不好。问题在于：它造的是一张乔布斯的海报，不是一副能戴上去看世界的眼镜。海报只能挂着看，眼镜能帮你看新东西。

## Primer

**女娲这个 skill 的目标，是把「这个人」变成一套能运行的认知操作系统**——他用什么镜片看世界、用什么直觉规则做判断、怎么表达、绝不会做什么、以及它做不到什么。一句话区分：捕捉的是他「怎么想」（HOW they think），不是他「说过什么」（WHAT they said）。

!diagram(main-flow)

**金句是说过的话，心智模型是思考的方式。** 「专注就是说不」是金句；而「面对任何资源分配问题，先问该砍什么，再问该做什么」是可运行的模型——你能拿它去推乔布斯对一个他从没见过的产品会怎么判断。前者只能背，后者能生成新答案。

**所以女娲不是先写，而是先查。** 它把一个人拆成六个互不重叠的维度——著作、长对话、碎片表达、他者评价、重大决策、时间线——每个维度派一个独立的 subagent 去调研，结果必须各自落盘成文件。一个 agent 一口气查不全，还会偏科。

**查完不能直接写。** 调研质量决定成品上限，垃圾进就是垃圾出。所以中间插了暂停：把六份调研的来源数、一手占比、矛盾点摆出来给你确认，你点头了才往下走。

**写的时候靠的是筛，不是抄。** 候选论点通常有十几个，女娲用三重验证（这套想法在他至少两个不同领域出现过吗？能用它推断他对新问题的立场吗？是不是只有他这么想？）把语录降级、把真信念留下，最后只取 3-7 个。宁可三个深刻的，不要十个浅的。

**最后给成品装一套「先做功课再开口」的工作流。** 这是人物 skill 从鹦鹉学舌升级成可靠顾问的关键——遇到涉及具体事实的问题，先 WebSearch 再回答，而不是凭训练语料编。

下面这张表，是同一句话两种交付的差别：

| 维度 | 默认 agent | 女娲 |
| --- | --- | --- |
| 调研 | 凭训练记忆 | 六维并行取证，必落盘，标一手/二手 |
| 中间产物 | 无，直接写 | 心智模型（HOW），不是金句（WHAT） |
| 遇到新问题 | 凭旧记忆编 | Agentic Protocol：先查再答 |
| 像不像 | 自己说像 | 盲读 100 字认人 + 独立子 agent 验 |
| 信息不足 | 照样写满 | 减少模型数，补写诚实边界 |

**它也有不防的地方。** 三重验证全靠主观判断，没有机器能拦住一个「听起来深刻其实是套话」的模型；质量脚本是浅检查，会漏会误报。这些后面都会摊开讲——一本诚实的解剖手册得先承认源 skill 的盲区。

## 难点预览

### 金句堆出来的是海报，不是眼镜
**坑:** 问乔布斯 skill 一个它没收录过的新问题，它把几句名言重新排列一下，给一段谁都能写的正确话。
**最值得学的一招:** 把中间产物从「他说过的话」换成「他思考的方式」——每个模型要能跨两个领域复现、能推断他对新问题的立场。
**维度:** 领域-认知
**深入:** stage-05 · A1

### 它会对截止日期后的事张口就编
**坑:** 问「乔布斯怎么看 Vision Pro」，它凭 2011 年前的旧记忆编一段像乔布斯的话，事实可能全错。
**最值得学的一招:** 给成品装 Agentic Protocol——把问题分成「需要事实/纯框架/混合」三类，需要事实的必须先 WebSearch 再开口。
**维度:** 行为
**深入:** stage-06 · A2

### 一个 agent 查一个人，必然偏科
**坑:** 单个上下文读了几篇文章就下笔，著作维度写得厚，决策和他者评价两栏几乎是空的。
**最值得学的一招:** 六个维度各派一个独立 subagent 并行查，且「不存文件的调研等于没做」——结果必须落盘成 `01-06.md`。
**维度:** 编排
**深入:** stage-03 · A3

### 用户说「想提升决策」，你根本不知道该蒸馏谁
**坑:** 默认 agent 要么直接问「你想蒸馏谁」把皮球踢回去，要么随手挑一个对不上需求的人，整条流水线白做。
**最值得学的一招:** 进门先分流——明确人名直接做，模糊需求走诊断，用一张需求维度表把困惑反推成 2-3 个候选人物。
**维度:** 需求
**深入:** stage-01 · A5

### 「我觉得挺像」是最不可信的验收
**坑:** 作者自评觉得写得像，旁人读 100 字却认不出是谁，满屏通用鸡汤。
**最值得学的一招:** 验收一律交给独立子 agent，用「删掉名字还能认出是谁」的盲读测试，作者不许自己给自己打分。
**维度:** 品味
**深入:** stage-07 · A6

## 章节逻辑

- 总览｜先让你看见默认做法会怎么坏，再给全景图
- 流程逐站｜跟着 agent 走完蒸馏乔布斯的七站，看每一站拦住什么
- 中间产物与数据流｜换个视角，跟着数据看每个文件谁写谁读、为什么长这样
- 源包导读｜想改写这个 skill 时，该读哪几个文件、各管什么
- 难点档案｜把全部难点做成卡片，标证据等级和可迁移性
- 上手练习｜拿一个新领域的任务，自己拼一套迷你 skill
- 术语表｜几个跨章承重的词，随用随查
- 带走工具箱｜全册标了「可偷」的招，自动汇总在这里
