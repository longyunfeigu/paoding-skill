## 骨架模式

把女娲从「造人物 skill」这层皮剥掉，剩下的骨架适用于任何「把某种隐性能力提炼成可运行 skill」的任务：

```text
分流澄清 → 多维并行取证（落盘） → 检查点暂停 → 表征化提炼（筛而非抄）
        → 装「先做功课再开口」协议 → 独立验收（回炉有上限）
```

四条不变量，换领域也不能丢：

- **中间产物是 HOW 不是 WHAT。** 提炼出的是可迁移的模型/规则，不是原始素材的摘抄——否则遇到新问题就崩（A1）。
- **阶段之间有暂停门。** 上一段质量决定下一段上限的地方，停下来量化确认，把返工提前到最便宜处（A4）。
- **验收不许自评。** 主观标准交独立裁判，用可判测试，作者对自己的产物脸盲（A6）。
- **信息不足就降级，不靠编填满。** 宁要诚实的 60 分（A7）。

## 新场景

你要给团队做一个 **「资深 SRE 故障复盘」skill**：输入一次线上事故（一堆日志、监控截图、值班记录），输出一份像资深 SRE 写的复盘——不只复述发生了什么，还能指出系统性的故障模式和下次该加的护栏。

这不是人物蒸馏，但它和女娲是同一类任务：把一种「老师傅脑子里的隐性判断力」固化成一个能跑的 skill。

## 任务

- 给这个 SRE skill 设计入口分流：用户可能丢「这次 P0 帮我复盘」（明确事故），也可能丢「我们老是半夜挂，想搞个复盘机制」（模糊需求）。照 A5 写两条路。
- 设计「多维取证」的维度（对标 A3 的六维）：故障复盘该并行查哪几栏？比如时间线、监控指标、变更记录、值班人证词、历史相似事故。每栏落盘成独立文件。
- 在「取证」和「提炼」之间放一个检查点（A4）：用什么摘要让用户确认「证据齐了再往下」？
- 设计提炼的筛子（对标 A1 + 三重验证）：怎么判断「这是一条可迁移的故障模式」而不是「这次事故的一次性细节」？
- 给成品装一段 Agentic Protocol（A2）：复盘 agent 遇到「当前 CPU 水位」这种要事实的问题时，研究维度该是什么（从 SRE 的核心关注点反推，而不是通用搜索）？
- 设计独立验收（A6）：怎么验「这份复盘像不像资深 SRE 写的、而不是通用事后总结」？

## 参考答案

一个能跑的骨架大概长这样（你的版本可以不同）：

- **入口分流**：明确事故 ID → 直接复盘；模糊「想要复盘机制」→ 先诊断是要事后模板还是实时告警，反推 2-3 个候选方向。
- **多维取证（五维并行，各落盘）**：`01-timeline.md`（事故时间线）、`02-metrics.md`（监控指标）、`03-changes.md`（变更/发布记录）、`04-oncall.md`（值班人证词）、`05-similar.md`（历史相似事故）。硬令：不落盘等于没查。
- **检查点**：一张表摆出五维各有几条证据、关键指标缺没缺，用户点头才提炼。
- **表征化提炼**：候选故障模式过三重验证——这个模式在两次以上事故里出现过吗（跨域复现）？能用它预测下次哪里会挂吗（生成力）？是不是这套系统特有、换个架构不成立（排他性）？过了的写成「故障模式卡」，没过的降级成「这次的偶发细节」。
- **Agentic Protocol**：从 SRE 的核心关注点（饱和度、错误率、延迟、变更）反推研究维度，遇到「当前水位多少」这类问题强制先查监控，不凭印象答。
- **独立验收**：派一个没参与写的 agent，盲读复盘结论，判断「这是有系统性洞察的复盘，还是一份谁都能写的『加强监控、完善流程』套话」。

骨架一模一样，换的只是维度名和筛子的判据。这就是 A1-A7 这批「可迁移性=高」的卡能跨领域复用的意思。

## 下一步

**作者:**
- 把你设计的迷你 skill 骨架写成一页 `SKILL.md` 草稿，标出哪几步是暂停门、哪步是独立验收。
- 挑骨架里最容易偷工的一步（多半是「检查点」或「独立验收」），想清楚省了它会在哪暴雷。

**偷招的人:**
- 下次你要把任何「老师傅的隐性判断力」做成工具，先抄这条骨架，再逐卡问「这一步我的领域对应什么」。
- 三重验证（A1）、检查点暂停（A4）、盲读认人（A6）这三招几乎在任何提炼/审校任务里都能单独拿走用，不必整套搬。
