h1: 源包导读
summary: 想改写女娲、或把它的某个机制搬进自己的 skill 时，该读哪几个文件、各管什么、读到什么程度。
---

## 总框架

女娲这个包按职责分四层，不按目录字母序：

- **入口调度层**：`SKILL.md`。一个文件装下从分流到精炼的九步流程，是唯一的总控。
- **任务认知层**：`references/extraction-framework.md`。回答「怎么判断一个论点是不是真信念」这个最难的认知问题。
- **呈现层**：`references/skill-template.md`。规定最终产物长什么样。
- **工具层**：`scripts/` 四个脚本，替 agent 干掉字幕清洗、调研统计、质量快检这些易错杂活。
- **校准层**：`examples/` 十五个已生成的人物 skill。它们是样例，不是规范——可以照着看「成品该有多厚」，但不能当成规则来源。

## 入口文件导读

`SKILL.md` 是女娲的全部大脑，644 行装下整条流水线，其它文件都是它在某一步点你去读的。读它就是读九个 Phase 的顺序。

开头「核心理念」一句话定调：女娲提炼的是 HOW they think，不是 WHAT they said。这句话不是口号，它决定了后面每一步——为什么要六维取证而不是摘金句，为什么中间产物是心智模型而不是语录合集。先抓住这句，后面才不会读散。

Phase 0 是入口分流：判断用户给的是明确人名（走直接路径 Phase 0A）还是模糊需求（走诊断路径 Phase 0B）。0A 确认对象和用途，最关键的是问一句「你手上有没有一手语料」；0B 用一张需求维度表，把「我想提升决策」这类困惑反推成 2-3 个候选人物。这一步决定了整条流水线为谁而跑。

Phase 0.5 在调研之前先建好自包含目录，并立下第一条红线：所有调研文件必须落在 skill 目录内部，复制走就能用。Phase 1 是六个并行 subagent 按维度采集，配一张信息源黑名单（知乎、微信公众号、百度百科永久排除）和「不存文件的调研等于没做」的落盘令。

Phase 1.5 和 Phase 2.5 是两个暂停检查点，把上一段产出摆出来让用户拍板，理由是「在这里拦截比在 Phase 4 返工成本低得多」。Phase 2 是提炼，它把判断标准移到了 `extraction-framework.md`，所以你要判断「一个模型够不够格」时，得翻那个文件。

Phase 3 构建时套用 `skill-template.md`，但其中的「回答工作流（Agentic Protocol）」不在模板里、要按心智模型现推——这是人物 skill 从鹦鹉学舌升级为可靠顾问的关键一段。Phase 4 用独立子 agent 跑三测试避免自评偏差，Phase 5 再做一轮双 agent 精炼。

贯穿全程还有一条总红线：宁可生成一个诚实标注局限的 60 分 skill，也不要一个看着完美实则编造的 90 分 skill。文末的「特殊场景」补了几条分支——主题 skill、中国人物、冷门人物、蒸馏用户自己——用到时再回来查。

## 引用关系

谁把你送到哪：

```text
SKILL.md
 ├─ Phase 2  → references/extraction-framework.md   （三重验证、质量自检清单）
 ├─ Phase 3  → references/skill-template.md          （成品骨架）
 ├─ Phase 1  → scripts/download_subtitles.sh         （取字幕）
 │            → scripts/srt_to_transcript.py          （清洗字幕）
 ├─ Phase 1.5→ scripts/merge_research.py             （检查点摘要）
 └─ Phase 4  → scripts/quality_check.py              （六项快检）
```

`SKILL.md` 是放射状中心，其余文件都只在某一个 Phase 被点名。读源包就是读这张「谁在第几步点我去哪」的图。

## 承重文件

### SKILL.md

**文件类型:** 入口调度层
**先给读者搭桥:** 如果你只读一个文件，就读它。它是女娲的总控，九个 Phase 的顺序和所有红线都在这里，其它文件都是它在某一步让你打开的。
**文件里实际讲了什么:** 开头用「捕捉 HOW they think 不是 WHAT they said」定调，决定了后面为什么要六维取证而非摘金句。主线是九个 Phase：Phase 0 分流判断人名还是模糊需求，Phase 0.5 建自包含目录，Phase 1 派六个 agent 并行采集并立下信息源黑名单，Phase 1.5 和 2.5 两个暂停检查点让用户拍板，Phase 2 提炼，Phase 3 套模板并现推 Agentic Protocol，Phase 4 用独立子 agent 验证，Phase 5 双 agent 精炼。关键转折是那条总红线：宁要诚实的 60 分，不要编造的 90 分。
**读它时先抓什么:** 先抓「HOW 不是 WHAT」这句定调，再抓九个 Phase 的先后和两个检查点的位置。
**它把细节交给谁:** 提炼标准交给 `extraction-framework.md`，成品骨架交给 `skill-template.md`，字幕和统计交给 `scripts/`。
**读完你应该能复述:** 从一句话到一个成品 skill，中间要经过哪九步、在哪两步必须停下来让用户确认。
**可以先略过什么:** 文末「特殊场景」的主题 skill / 中国人物 / 冷门人物分支，用到对应场景时再回来读。

### references/extraction-framework.md

**文件类型:** 任务认知层
**先给读者搭桥:** 女娲最难的一步是「怎么知道某个论点是这个人真正的思维方式，而不是他随口一说」。这个文件就是回答这个问题的，它把这种判断从主观感觉变成一套能照着做的筛子。
**文件里实际讲了什么:** 核心是心智模型的三重验证：跨域复现（在两个以上领域都出现）、生成力（能推断他对新问题的立场）、排他性（不是所有聪明人都这么想），三道全过才算心智模型，过一两道降级为决策启发式。然后给表达 DNA 的量化方法，比如从二十个段落里统计平均句长、疑问句比例、类比密度。中段讲矛盾的三种类型（时间性、领域性、本质性张力）以及为什么矛盾不该被抹平。文末是一份质量自检清单，Phase 3 收尾和 Phase 4 质量验证会逐项对照。
**读它时先抓什么:** 先抓三重验证的三个判据，这是整个提炼步骤的筛子。
**它把细节交给谁:** 质量自检清单交给 `quality_check.py` 做机器快检的那部分。
**读完你应该能复述:** 一个候选论点要满足哪三个条件才配叫心智模型，不满足时怎么降级。
**可以先略过什么:** 句式指纹的六个统计维度，除非你要亲手量化某人的表达风格。

### references/skill-template.md

**文件类型:** 呈现层
**先给读者搭桥:** 这个文件规定女娲交出的成品长什么样。把它当成一张填空骨架：提炼出的东西按它的格子一格一格填进去，就是一个能激活的人物 skill。
**文件里实际讲了什么:** 它按顺序定义了成品的每个 section：frontmatter 描述、角色扮演规则、身份卡、核心心智模型、决策启发式、表达 DNA、时间线、价值观与反模式、智识谱系、诚实边界、调研来源。每个 section 给了占位格式，比如心智模型要带「一句话、证据、应用、局限」四项。关键转折是：它只是地板不是天花板——对照 `examples/` 会发现成品在它之上自己长出了 CHECKPOINT、失败模式 Fallback 树这些模板没规定的结构。
**读它时先抓什么:** 先抓心智模型 section 的四件套格式，那是成品的主体。
**它把细节交给谁:** 「回答工作流」一段它没规定，交回 `SKILL.md` 的 Phase 3 现推。
**读完你应该能复述:** 一个合格的人物 skill 至少要有哪些 section，每个 section 装什么。
**可以先略过什么:** frontmatter 的触发词写法，套用时照抄即可。

### scripts/

**文件类型:** 工具层
**先给读者搭桥:** 这四个脚本替 agent 干掉几样手做易错的杂活：取字幕、清洗字幕、统计调研、质量快检。读它们是为了知道哪些活可以交给脚本，以及脚本在哪里会骗你。
**文件里实际讲了什么:** `download_subtitles.sh` 按「人工字幕到中文到英文到自动字幕」四级 fallback 取 YouTube 字幕。`srt_to_transcript.py` 把字幕去时间戳、去序号、去重复行，再按 200 字或句末标点重新分段。`merge_research.py` 扫描六份调研生成检查点摘要表，但它拿 URL 数当来源数、关键词命中数当一手占比，所以数值是近似。`quality_check.py` 用正则快检六项硬标准，会误报，比如把 `1.` 编号的诚实边界数成 0 条。
**读它时先抓什么:** 先抓两个分析脚本的局限——`merge_research` 和 `quality_check` 的读数都要人脑覆盖。
**它把细节交给谁:** 取到的字幕交给 `srt_to_transcript.py` 清洗后存进 `references/sources/transcripts/`。
**读完你应该能复述:** 哪些活脚本能替你做，哪两处脚本输出不能照单全收。
**可以先略过什么:** `download_subtitles.sh` 里那个用 `/tmp/.ytdlp_marker` 判断新文件的小瑕疵，除非你要修这个脚本。

## 阅读优先级

### 必读
**文件:** `SKILL.md`
**原因:** 不读它就完全不知道流程长什么样；九个 Phase 的顺序和所有红线都只在这里。

### 提炼时读
**文件:** `references/extraction-framework.md`
**原因:** 走到 Phase 2 要判断「这个模型够不够格」时，筛子在这个文件里。

### 构建时读
**文件:** `references/skill-template.md`
**原因:** Phase 3 组装成品时照它的格子填；想知道成品该有哪些 section 也看它。

### 修改/调试时读
**文件:** `scripts/merge_research.py`, `scripts/quality_check.py`
**原因:** 这两个脚本的读数是近似，怀疑统计或质检结果不对时，回来看它们怎么算的。

### 查阅
**文件:** `examples/*-perspective/`
**原因:** 想看成品的真实厚度和结构演化时翻一两个；记住它们是校准样例，不是规范源。

## 通读路线

第一遍只读 `SKILL.md`，从头到尾把九个 Phase 的顺序和两个检查点的位置记住，别钻任何细节。第二遍带着「怎么判断真信念」这个问题去读 `extraction-framework.md` 的三重验证，再回 `SKILL.md` 的 Phase 2 对上号。第三遍读 `skill-template.md`，同时翻一个 `examples/`（比如 steve-jobs）对照，感受成品在模板之上长出了什么。脚本只在你要改它、或怀疑某个统计读数时才逐行读——平时知道它们替你干了什么活就够了。
