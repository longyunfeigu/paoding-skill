## stage-01 入口分流与澄清

**kicker:** 还没开搜，先分清用户给的是什么
**summary:** 判断输入是明确人名还是模糊需求，分两条路；明确人名也要补问一句有没有一手语料。
**面包屑:** 分流 → 建目录 → 采集 → 检查点 → 提炼 → 构建 → 验证

### 场景再现

我手上只有用户的一句话：

> 帮我做一个乔布斯的思维 skill

这句话其实给了我两个信号：一个明确的人名（乔布斯），一个隐含的用途（思维顾问）。源 skill 第一步就逼我先认这个信号，而不是直接开搜：

> | 用户输入 | 路径 | 示例 |
> | --- | --- | --- |
> | 明确的人名/主题 | **直接路径** → Phase 0A | 「蒸馏芒格」「做一个费曼skill」 |
> | 模糊的需求/困惑 | **诊断路径** → Phase 0B | 「我想提升决策质量」 |

「乔布斯」落在第一行，走直接路径。但在开搜之前，还有一句必须问出口。

### 难点

**领域难点:** 确无
**行为难点:** 默认 agent 收到输入就开搜：模糊需求时它要么把皮球踢回去（「你想蒸馏谁？」），要么随手挑一个对不上的人，整条流水线白做；明确人名时它跳过「你手上有没有一手语料」这一问，直接走网络搜索，把用户手里那本完整传记 PDF（最高权重的素材）漏在门外（证据：作者证词）

### 预测点

如果是你来设计这一步：怎么用最少的提问，既能把模糊需求收敛到一个具体对象，又不会变成让用户填问卷？先想想你的方案，再看女娲怎么在「最多问 2 轮」的约束下做这件事。

### 机制与产出

女娲把澄清拆成两条路。明确人名走 Phase 0A，确认五件事，其中第五件最容易被忽略：

> 5. **本地语料**：「你手上有没有这个人的一手素材？比如书籍PDF、演讲/访谈transcript、视频字幕、个人博客导出等。有的话直接丢给我，比网上搜的质量高得多。」

模糊需求走 Phase 0B，用一张需求维度表把困惑反推成候选对象，并给追问限流：

> 追问原则：
> - 最多问2轮，不要变成问卷调查
> - 如果用户已经表达得足够清晰，不追问，直接推荐

这两条机制各管半边：本地语料一问，堵住「漏掉最高权重素材」；两轮限流，堵住「把澄清做成审讯」。

### 真实产出

乔布斯是明确人名，澄清后我带着这样一份确认进入下一步：

```text
对象：史蒂夫·乔布斯（确认无误）
聚焦：全面画像
用途：思维顾问
新建 or 更新：新建（.claude/skills/ 下无 steve-jobs-perspective）
本地语料：无 → 走纯网络搜索模式
```

### 收尾

**可偷的招:** 当用户的需求模糊到不知道该研究谁时 → 先用一张「需求维度 → 方法论方向」对照表反推 2-3 个候选，让他选，而不是逼他自己想清楚。
**对应档案:** A5
**下一步靠这个:** 确认了对象和「无本地语料」，下一步才能决定建什么样的目录、用哪种采集模式。

### 阶段速查
**这一步收到什么:** 用户一句话（人名或模糊需求）
**skill 让我读什么:** Phase 0 分流表、Phase 0A 五问、Phase 0B 需求维度表
**我不能直接做什么:** 不能收到输入就开搜
**我做什么:** 判路径 → 澄清对象/用途/语料
**我产出什么:** 一份确认（对象、聚焦、用途、是否有本地语料）
**机制线索:** 反编造线的起点——先把对象认准
**下一步谁用它:** stage-02 据此建目录、定采集模式
**自由度:** 高（追问节奏由我把握，但不许超 2 轮）

## stage-02 建自包含目录

**kicker:** 调研之前先搭骨架
**summary:** 确认后立刻建好 skill 目录，所有调研文件必须落在 skill 内部，复制走就能用。
**面包屑:** 分流 → 建目录 → 采集 → 检查点 → 提炼 → 构建 → 验证
**接上一步:** 拿着「蒸馏乔布斯、无本地语料」的确认，开搜之前先把容器建好。

### 场景再现

我已经知道要做什么了，手痒想直接派 agent 去搜。源 skill 在这里按住我：先建目录，而且对文件放哪有死规定。

> ### Phase 0.5: 创建Skill目录
>
> **收到确认后立即执行**，在调研之前完成

骨架长这样：

> - `SKILL.md`（最终产物）
> - `scripts/`（工具脚本）
> - `references/research/`（每个 Agent 的调研结果，必存）
> - `references/sources/`（一手素材：books / transcripts / articles）

### 难点

**领域难点:** 确无
**行为难点:** 默认 agent 会把调研结果留在对话里，或图省事写进项目里某个外部目录（比如 `07-调研与分析/`）。结果 skill 不自包含——别人复制这个目录想直接用，发现它依赖一堆不在包里的文件，开源分发直接废掉（证据：作者证词）

### 预测点

你会用什么办法，确保几个并行的 subagent 不会把文件写到 skill 目录外面去？是靠提醒，还是靠一条不留余地的规则？

### 机制与产出

女娲用一条没有商量余地的规则锁死位置：

> **所有调研文件必须存在skill目录内部**（`references/research/`），绝对不要存到 `07-调研与分析/` 或其他外部目录。Skill必须是自包含的——复制整个skill目录就能独立使用，不依赖任何外部文件。这是为开源分发设计的核心原则。

配一条同样硬的落盘令，专治「查了不写」：

> 每个subagent必须把调研结果写入对应的md文件。不存文件的调研等于没做。

### 真实产出

这一步交给下一步的，是一个空的、但结构完整的容器：

```text
.claude/skills/steve-jobs-perspective/
├── SKILL.md                 # 占位，最后填
├── scripts/
└── references/
    ├── research/            # 01-06.md 等着六个 agent 来写
    └── sources/
        ├── books/
        ├── transcripts/
        └── articles/
```

### 收尾

**可偷的招:** 当你要派多个 subagent 协作产出一个可分发的包时 → 开工第一步先建好自包含目录，并写死「产物只许落在包内」，别等写完了再搬家。
**对应档案:** A3
**下一步靠这个:** 六个 agent 各自有了明确的落盘地址，才能并行而不打架。

## stage-03 六 Agent 并行采集

**kicker:** 一个人拆成六维，六个 agent 同时挖
**summary:** 著作/对话/表达/他者/决策/时间线各派一个 subagent，按信息源优先级和黑名单选源，结果各自落盘并标可信度。
**面包屑:** 分流 → 建目录 → 采集 → 检查点 → 提炼 → 构建 → 验证
**接上一步:** 目录建好了，六个落盘地址就位，现在同时放六个 agent 出去。

### 场景再现

我面对的是「把乔布斯查全」。如果我一个上下文从头查到尾，必然偏科——读到几篇精彩的演讲分析就停不下来，决策记录和外部批评两栏空着。源 skill 把这件事拆成六个互不重叠的维度，每维一个 agent：

> | Agent | 搜索目标 | 输出文件 |
> | --- | --- | --- |
> | 1 著作 | 书、长文、论文 | `01-writings.md` |
> | 2 对话 | 播客、长视频、AMA | `02-conversations.md` |
> | 3 表达 | Twitter/X、短文 | `03-expression-dna.md` |
> | 4 他者 | 他人分析、书评、批评 | `04-external-views.md` |
> | 5 决策 | 重大决策、转折点 | `05-decisions.md` |
> | 6 时间线 | 完整时间线 + 最近 12 个月 | `06-timeline.md` |

### 难点

**领域难点:** 「把一个人查全」装不进单个上下文，而且哪些来源可信、哪些会污染人设，不是凭直觉能分的——中文生态里知乎洗稿、公众号无法验证、百度百科陈旧，用了就把假信息焊进人设（证据：作者证词）
**行为难点:** subagent 查完容易不落盘，把发现留在自己的回答里就算完事；遇到矛盾信息倾向和稀泥调和成一个顺滑版本，把最有信息量的张力抹平了（证据：作者证词）

### 预测点

六个 agent 同时在搜，你怎么保证：一、它们不会都去搜同样的东西？二、搜到的东西不会烂在某个 agent 的上下文里？三、它们不会偷偷用知乎凑数？先设计你的三道关卡，再看女娲的。

### 机制与产出

第一道关卡是分工表本身——六个维度互不重叠，天然不撞车。第二道是落盘硬令（见 stage-02）。第三道是把选源标准写死，不靠 agent 自觉：

> #### 信息源黑名单（永远排除）
> - **知乎**：洗稿严重、信息失真率高，不作为任何维度的来源
> - **微信公众号**：封闭生态、无法验证、大量二手转述，不作为来源
> - **百度百科/百度知道**：信息陈旧且不可靠

再加一条处理矛盾的规矩，专治和稀泥：

> 发现矛盾时保留矛盾，不要和稀泥

!steal(六维取证目录 ｜ 直接抄走 ｜ 系统调研任何一个人或主题)
> 下次你要系统了解一个人——写人物稿、做尽调、给某位专家建档——别一头扎进去乱搜。先照搬这六个维度建六个文件：著作、长对话、碎片表达、他者评价、重大决策、时间线。它的好处是逼你把「他者评价」「重大决策」这种你自己容易跳过的维度也填上，天然防偏科。

选源标准也值得单独拿走，它和上面那张目录是一对：目录管「查哪几个维度」，黑名单管「信任哪些来源」。

!steal(中文人物信息源黑名单 ｜ 直接抄走 ｜ 任何中文人物/主题调研)
> 你查中文人物时，把这三个来源直接拉黑：知乎、微信公众号、百度百科。换成 36氪、晚点 LatePost、财新、极客公园这类权威媒体，人物访谈优先小宇宙原始音频和 B 站原视频（非搬运号）。这一条和女娲无关，是任何中文调研都能用的选源底线。

### 真实产出

这是 Agent 3（表达）写进 `03-expression-dna.md` 的真实片段——注意它不是收集金句，而是拆解金句背后的机制：

> **"One more thing..."**
> - 首次出现：1998年Macworld San Francisco
> - [推断] 这是一个**叙事装置**而非即兴发挥——每次使用都经过精确计算。当他担心一场 Keynote 的高潮不够强时，就会启用 "one more thing" 作为结构补丁

每条信息都带 `[一手]` / `[二手]` / `[推断]` 标记，可信度一眼可辨——这正是落盘令要的东西。

### 收尾

**可偷的招:** 当一个调研任务大到单个上下文会偏科时 → 先把它切成几个正交维度，每维一个独立 agent，并强制各自落盘成文件，别让任何发现只活在某个 agent 的脑子里。
**对应档案:** A3
**下一步靠这个:** 六份带可信度标记的调研档案，是下一步检查点要盘点的全部物料。

### 阶段速查
**这一步收到什么:** 空目录 + 蒸馏对象
**skill 让我读什么:** 六 Agent 分工表、信息源优先级/黑名单、Agent prompt 模板
**我不能直接做什么:** 不能一个上下文查到底、不能用黑名单来源、不能不落盘
**我做什么:** 派六个并行 subagent，各管一维度、各自落盘、标一手/二手
**我产出什么:** `references/research/01-06.md` 六份调研档案
**机制线索:** 反编造线 + 编排线的主战场
**下一步谁用它:** stage-04 检查点据此盘点质量
**自由度:** 中（维度固定，但每维搜什么由 agent 展开）

## stage-04 调研 Review 检查点

**kicker:** 写之前先验货，垃圾不进下一步
**summary:** 六份调研汇总成一张质量摘要表，暂停展示给用户确认，调研不过关就地补，不带病往下走。
**面包屑:** 分流 → 建目录 → 采集 → 检查点 → 提炼 → 构建 → 验证
**接上一步:** 六份调研档案到手，先别急着提炼，停下来盘一次货。

### 场景再现

六个 agent 都回来了。我很想立刻开始提炼心智模型——但源 skill 在这里设了一道暂停门：先把调研质量摆出来给用户看。手工去数六个文件各有多少来源、一手占比多少，又烦又容易错，所以它给了脚本：

> 调研摘要生成（Phase 1.5用）：`python3 [skill目录]/scripts/merge_research.py <skill目录>`
> - 自动扫描 `references/research/01-06.md`，统计来源数、一手/二手占比、关键发现

### 难点

**领域难点:** 手工统计六个文件的来源数和一手占比，既烦又容易数错；但用脚本近似又会失真——它拿 URL 数当来源数、拿关键词命中数当一手占比，读数得人脑覆盖（证据：实测）
**行为难点:** 默认 agent 不设检查点，调研一回来就埋头提炼，写到一半（甚至写完 400 行 SKILL.md）才发现某个维度全是营销稿、方向错了，返工成本极高（证据：作者证词）

### 预测点

如果让你在「调研完」和「开始写」之间插一道关，这道关该检查什么、由谁拍板？为什么不能等成品出来再检查？

### 机制与产出

机制有三件套：先强制暂停，再把六份调研压成一张摘要表，最后由用户拍板放不放行。

> **所有Agent完成后，暂停展示调研质量摘要**
>
> 用户确认调研质量OK → 进入Phase 2。
> 用户觉得某维度不够 → 补充调研后再继续。
>
> 这个检查点的意义：调研质量决定了最终Skill的上限。垃圾进垃圾出，在这里拦截比在Phase 4返工成本低得多。

### 真实产出

这是 `merge_research.py` 在 `examples/steve-jobs-perspective` 上**真跑**出来的摘要表：

```text
┌──────────────┬──────────┬──────────────────────────┐
│ Agent        │ 来源数量  │ 关键发现                  │
├──────────────┼──────────┼──────────────────────────┤
│ 著作          │ 24       │ 核心著作与一手文献…        │
│ 对话          │ 27       │ 核心访谈索引…              │
│ 表达          │ 26       │ Keynote 语言特征…          │
│ 他者          │ 29       │ 同事/竞争对手/系统性批评    │
│ 决策          │ 0        │ 早期决策/被逐出 Apple…     │
│ 时间线        │ 12       │ 早年/Apple 创立期…         │
├──────────────┼──────────┼──────────────────────────┤
│ 总来源数      │ 118      │ 一手占比: 134/244          │
│ 矛盾点        │ 5处      │ 著作: 争议。不妥协          │
└──────────────┴──────────┴──────────────────────────┘
```

注意「决策 0 来源」——决策档案明明写满了四段决策，只是没贴 URL，脚本拿 URL 数当来源数就报了 0。一手占比的 134/244 也是关键词命中数，不是真比例。脚本省了你点六个文件的力气，但读数这一步还得你来。

!steal(检查点暂停话术 ｜ 思路带走 ｜ 任何多阶段、上一段质量决定后续的流程)
> 你做任何「上一段质量决定下一段上限」的多阶段活——调研、数据清洗、需求确认——都值得在中间插一道暂停门：把上一段的产出量化成一张小摘要表，停下来让人（或你自己）拍板「够不够格往下走」。它的价值不在表格本身，在于把返工从最后一步提前到最便宜的那一步。

### 收尾

**可偷的招:** 当流程里上一段质量决定下一段上限时 → 在两段之间插一个量化摘要 + 强制暂停确认，别等成品出来才发现源头就错了。
**对应档案:** A4
**下一步靠这个:** 用户点头「调研够了」，提炼才有合格的原料；脚本的近似读数也提醒我哪几栏要人工复核。

## stage-05 框架提炼

**kicker:** 从十几个候选里筛出真信念
**summary:** 用三重验证把语录降级、把心智模型留下，取 3-7 个；同时提炼表达 DNA、反模式、内在张力和诚实边界。
**面包屑:** 分流 → 建目录 → 采集 → 检查点 → 提炼 → 构建 → 验证
**接上一步:** 调研验收通过，现在把六份原料炼成可运行的框架。

### 场景再现

我手上有六份调研，里面散着十几二十个候选论点——有的是乔布斯反复讲的真信念，有的只是他某次采访的随口一说。源 skill 不让我凭感觉挑，先要我读方法论：

> 先读取 `references/extraction-framework.md` 获取心智模型的三重验证方法论（跨域复现、生成力、自创术语），确保提炼质量。

### 难点

**领域难点:** 「哪个论点是他真正的心智模型、哪个只是场面话」想错就全错——错把语录当模型，成品就是漫画式人设，遇到新问题就崩；而且信息不足时还硬凑模型数，会编出听着深刻其实空洞的框架（证据：作者证词）
**行为难点:** 默认 agent 倾向把通用道理包装成「此人的独特见解」，再把调研里的矛盾抹平成一个顺滑版本，结果是个观点高度一致、毫无张力的假人（证据：作者证词）

### 预测点

给你十五个「乔布斯说过的话」，你怎么判断哪几个是能拿去推断他对新问题立场的「心智模型」，哪几个只是漂亮话？设计一个不靠主观感觉的筛子。

### 机制与产出

女娲的筛子是三道验证，候选必须三道全过才算心智模型：

> 1. **跨域复现**：在≥2个不同领域/话题中出现？
> 2. **生成力**：能推断此人对新问题的立场？
> 3. **排他性**：不是所有聪明人都这样想？
> 三重通过 → 心智模型；仅1-2重 → 降级为决策启发式；0重 → 丢弃

外加一条数量纪律和一条诚实纪律：

> 取 top 3-7 个。宁少勿多——3个深刻的模型远好于10个浅薄的原则
>
> 宁可生成一个诚实标注了局限的60分Skill，也不要生成一个看起来完美但实际上在编造的90分Skill。

### 真实产出

这是提炼后写进成品的「模型1」，注意它不止有正面，还自带失效边界——而且这个边界是乔布斯本人打脸的真实案例：

> ### 模型1: 聚焦即说不（Focus = Saying No）
> **一句话**：聚焦不是对你要做的事说 Yes，而是对其他一百个好主意说 No。
> **应用**：当面对产品功能列表、战略优先级、资源分配等「该做什么」的问题时——先问该砍什么。
> **局限**：说 No 需要极强的判断力。说错了 No 可能错过整个市场——我曾经对第三方 App 说 No（2007年坚持 Web Apps 就够了），一年后不得不 180 度大转弯开放 App Store。

!steal(心智模型三重验证 ｜ 直接抄走 ｜ 判断一个观点是真信念还是随口一说)
> 下次你读一个人的访谈、文章、语录，想判断「这是他真正信的，还是随口一说」，拿这三问过一遍：他在两个以上不同领域都这么想吗（跨域复现）？用这个想法能推出他对一件新事的立场吗（生成力）？是不是只有他这么想、换个聪明人不会（排他性）？三个都过才是真信念，过一两个降级成习惯，一个不过就是场面话。这套筛子跟造 skill 无关，读任何人都能用。

### 收尾

**可偷的招:** 当你要从一堆素材里提炼某人的「核心主张」时 → 别按「说得漂不漂亮」挑，按「跨域复现 / 生成力 / 排他性」三道验证筛，过不了的降级或丢弃。
**对应档案:** A1
**下一步靠这个:** 筛出的 3-7 个心智模型，既是成品的主体，也是下一步推导 Agentic Protocol 研究维度的依据。

### 阶段速查
**这一步收到什么:** 六份验收通过的调研档案
**skill 让我读什么:** extraction-framework.md（三重验证 + 质量自检清单）
**我不能直接做什么:** 不能凭感觉挑模型、不能信息不足硬凑、不能抹平矛盾
**我做什么:** 三重验证筛模型、量化表达 DNA、保留张力、写诚实边界
**我产出什么:** 心智模型表 / 决策启发式 / 表达 DNA / 内在张力 / 诚实边界
**机制线索:** 领域-认知核心——可迁移产物线在这里成型
**下一步谁用它:** stage-06 据此填模板、推导 Agentic Protocol
**自由度:** 中（筛法固定，取舍是主观判断最重的一环）

## stage-06 构建 SKILL.md

**kicker:** 套模板填充，再装一套「先做功课」的工作流
**summary:** 按 skill-template.md 组装成品，并根据心智模型反推出专属的 Agentic Protocol，让人物不只说得像、还做得像。
**面包屑:** 分流 → 建目录 → 采集 → 检查点 → 提炼 → 构建 → 验证
**接上一步:** 框架炼好了，现在把它装进一个标准的、能运行的 SKILL.md。

### 场景再现

提炼结果在手，我要把它组装成成品。源 skill 给了模板（`skill-template.md`）做骨架，但最关键的一段不在模板里、要现推——回答工作流。源 skill 解释了为什么非要它不可：

> 没有这个段落，人物Skill遇到需要事实的问题时会凭训练语料编造，而不是像真人一样先做功课再发言。这是人物Skill从「鹦鹉学舌」升级为「可靠思维顾问」的关键。

### 难点

**领域难点:** Agentic Protocol 的研究维度必须从这个人的心智模型反推，不能是通用的「搜索相关信息」——芒格看激励结构，乔布斯看产品体验，维度错了等于没装（证据：作者证词）
**行为难点:** 没有这段工作流，成品遇到涉及具体事实/截止日期后的问题会直接凭训练语料编，输出一个像本人、但事实可能全错的回答（证据：作者证词）

### 预测点

你要让一个「乔布斯 agent」遇到新产品时先去看真实评测再开口。这套「先查再答」的步骤，研究维度该怎么定——是给一份通用搜索清单，还是别的？

### 机制与产出

机制是一段三步工作流，其中研究维度按人定制：

> 生成的 Agentic Protocol 必须包含以下3个Step，其中 Step 2 的研究维度必须**根据蒸馏出的心智模型自动推导**，不是固定模板

推导方法是从心智模型反查此人分析问题时最关注什么：

> | 人物 | 核心心智模型 | → 推导出的研究维度 |
> | --- | --- | --- |
> | 芒格 | 多元思维模型、逆向思考、激励机制 | → 看护城河、看管理层激励、看最大风险 |
> | MrBeast | 注意力工程、测试迭代 | → 看竞品数据、看标题/缩略图 A/B 空间、看受众画像 |

### 真实产出

乔布斯的心智模型（聚焦、端到端控制、技术与人文交汇）被反推成了这样的研究维度——和芒格的完全不同：

> ### Step 2: 乔布斯式研究
> #### 看产品体验
> 1. **实际使用**：这个产品的实际使用体验如何？用户评价说什么？
> #### 看设计细节
> 1. **交互设计**：交互逻辑是否简洁？有没有多余的步骤？
> #### 看技术路线
> 1. **垂直整合度**：这个产品控制了多少体验链条？关键环节在谁手上？

成品甚至在 Step 之间加了 `CHECKPOINT` 自检（「问题涉及 2014 年后的产品吗？→ 是 → 强制 Step 2」）——这是示例在模板之上自己长出来的结构。

!steal(回答工作流的问题三分类 ｜ 直接抄走 ｜ 让任何 LLM 角色先做功课再开口)
> 你给任何 AI 角色/agent 写提示词，想让它别张口就编，可以直接抄这个三分类：进来先判断——需要事实的问题（涉及具体产品/公司/数字）就强制先搜，纯框架问题（抽象理念）直接答，混合问题先取事实再用框架。再配一句兜底：拿不准就默认去搜。这套分流和「人物」无关，任何怕模型编造的场景都能用。

### 收尾

**可偷的招:** 当你要让一个角色 agent「做得像」而不只是「说得像」时 → 给它装一段先做功课的工作流，且研究维度要从它的核心模型反推，不要套通用搜索清单。
**对应档案:** A2
**下一步靠这个:** 一份完整的 SKILL.md 落盘，下一步才有东西可验证。

## stage-07 质量验证与精炼

**kicker:** 验收不许自己给自己打分
**summary:** 用脚本过六项硬标准，再派独立子 agent 跑已知/边缘/风格三测试，最后双 agent 精炼；不通过就回炉，最多两次。
**面包屑:** 分流 → 建目录 → 采集 → 检查点 → 提炼 → 构建 → 验证
**接上一步:** 成品落盘，现在进验收——而且是独立验收。

### 场景再现

SKILL.md 写完了，我很想自己读一遍说「挺好，交付」。源 skill 不允许——它把验收交给独立的子 agent，理由直白：

> 用子agent执行3项测试（独立于主agent，避免自评偏差）

它还给了一个能机器跑的快检：

> 质量自检（Phase 4用）：`python3 [skill目录]/scripts/quality_check.py <SKILL.md路径>`

### 难点

**领域难点:** 「有辨识度、不像通用 AI 味」这个验收标准本身说不清、也难固化成机器能查的规则（证据：作者证词）
**行为难点:** 让主 agent 自己验自己刚写的东西，它会系统性放水——读到的是「我当时想表达的意思」，不是纸面上真实的句子（证据：作者证词）

### 预测点

「像不像这个人」这种说不清的标准，你怎么验收才不至于自己骗自己？谁来当这个裁判，用什么测试？

### 机制与产出

机制分三层：三项独立测试、一张把「好」量化的通过标准表，外加一个独立裁判。风格测试用的是盲读认人：

> #### 4.3 风格测试（Voice Check）
> 用Skill写一段100字分析，判断：
> - 有此人的表达特征？
> - 不是通用AI味鸡汤？
> - 不是原话拼凑？

通过标准表把「好」量化到可判：

> | 检查项 | 通过标准 | 不通过信号 |
> | --- | --- | --- |
> | 表达DNA辨识度 | 读100字能认出是谁 | 像通用ChatGPT |
> | 一手来源占比 | >50% | 主要依赖二手转述 |

Phase 4 通过后还有 Phase 5 双 agent 精炼。回炉有上限，防止无限打磨：

> **迭代上限**：Phase 2→4最多循环2次。

### 真实产出

`quality_check.py` 在成品上**真跑**的结果——乔布斯 6/6 全过：

```text
质量检查: SKILL.md
  心智模型数量   ✅ PASS  6个心智模型 ✅
  表达DNA辨识度  ✅ PASS  表达DNA特征: 21项 ✅
  诚实边界      ✅ PASS  诚实边界: 3条 ✅
结果: 6/6 通过  🎉 全部通过，可以交付
```

但同一个脚本跑芒格的成品时报「诚实边界 0 条 FAIL」——芒格成品其实有 6 条诚实边界，只是用 `1.` `2.` 编号，而脚本只数 `-` `*` 项目符号。这道脚本门是廉价快检，会误报，真正的裁判还是独立子 agent。

!steal(盲读认人测试 ｜ 直接抄走 ｜ 任何模仿写作或角色一致性的验收)
> 你写完一段模仿某人风格的文字——演讲稿、角色台词、品牌文案——拿这个测试验收：把名字遮掉，给一个没参与写作的人读 100 字，问「认得出这是谁吗」。认得出才算有辨识度，认不出说明你写的是通用鸡汤。关键是别自己判——作者对自己的字脸盲，得找个没下过笔的人当裁判。

### 收尾

**可偷的招:** 当验收标准是「像不像 / 好不好」这种说不清的东西时 → 把裁判换成没参与生产的独立 agent，用「盲读能不能认出」这类可判测试，并给重做设次数上限。
**对应档案:** A6
**下一步靠这个:** 三测试通过、双 agent 精炼应用完，成品才算可交付——这里把整条流水线的账结清。

### 阶段速查
**这一步收到什么:** 写好的 SKILL.md
**skill 让我读什么:** Phase 4 通过标准表、quality_check.py、Phase 5 双 agent 精炼
**我不能直接做什么:** 不能自评、不能无限回炉
**我做什么:** 脚本快检，再派独立子 agent 跑三测试，最后双 agent 精炼
**我产出什么:** 验证报告 + 交付版 SKILL.md
**机制线索:** 防自评线的终点
**下一步谁用它:** 用户（交付）
**自由度:** 低（标准固定，裁判必须独立）
