## 产物卡

### references/research/01-06.md(六份调研档案)

**谁写它:** 6 个并行调研 agent,每路写自己那份(01 著作、02 对话、03 表达、04 他者、05 决策、06 时间线)
**谁读它:** merge_research.py(出检查点摘要)、提炼站(唯一原料)、成品 SKILL.md 附录(永久引用)
**它管什么:** 「他在这个面向留下过什么证据」——每条信息带来源 URL 和可信度标记,区分「他说过的/别人说他的/我推断的」
**它不管什么:** 不做提炼判断。档案里不写「他的心智模型是 X」,只存原始证据;筛选是下一站的事
**为什么长这样:** 直觉做法是 6 路调研汇报进对话、主 agent 边听边总结——两步并一步,出错没法回溯:提炼错了分不清是「料错了」还是「筛错了」。拆成六仓落盘档案后,检查点能单独验料,附录能永久引用,换一个 agent 重跑提炼也不用重新调研
**写错会坏什么:** 档案里混入无来源断言,三重验证的「证据」就成了空转——筛子还在,料已经是假的;成品附录引用一个编造的 URL,读者顺藤摸瓜时信任崩塌

下面是真实标本,摘自 `06-timeline.md` 第一节(来源:源包 examples/sun-yuchen-perspective):

```markdown
**2007-2008年** — 利用青海户籍身份参加高考(被外界称为「高考移民」),
总分650分,距北大录取线差3分,但凭借新概念一等奖+自主招生加分,
被**北京大学历史系**录取。(来源:中新网、搜狐教育、新浪教育)
```

逐字段看它编码了什么设计决策:粗体年份是时间线的索引键,提炼站靠它排「思想转折点」;「被外界称为」是立场标记——这是他者的说法,不是本人叙事,提炼时不会误当成自我认知;句尾括号的来源清单,是这条信息能不能被信任的依据。写丢了来源,这条就降级成不可用的传闻。

### sources/(一手素材仓)

**谁写它:** 用户(丢进来的书籍 PDF、transcript)+ 字幕脚本链(download_subtitles.sh → srt_to_transcript.py 的产物)
**谁读它:** 6 个调研 agent——本地语料模式下它是第一优先级信息源,网络搜索只补缺口
**它管什么:** 未经二手过滤的原文:books/、transcripts/、articles/ 三个子仓
**它不管什么:** 不存调研结论。素材和档案分开放,「原文」和「我对原文的整理」永不混仓
**为什么长这样:** 直觉做法是把用户给的 PDF 读完就扔,只留笔记。分仓保存原文后,提炼期对档案有疑问可以回到原文复核;信息源权重表里「用户提供的一手素材」排最高权重,这个仓就是最高权重证据的实体
**写错会坏什么:** 素材混进档案目录,1.5 检查点的来源统计会把一本 300 页的书和一条 markdown 笔记同等计数,摘要表失真

### 检查点 1.5 调研摘要表(对话内产物)

**谁写它:** merge_research.py 扫描 6 份档案自动生成(或主 agent 手工汇总)
**谁读它:** 用户——这是流程第一次暂停,等用户说「继续」
**它管什么:** 调研质量的可扫视压缩:每路来源数、关键发现、矛盾点、信息不足维度
**它不管什么:** 不替用户做判断。表只陈列「著作 8 篇、对话 5 段、矛盾 2 处」,够不够格往下走由用户拍板
**为什么长这样:** 直觉做法是把 2087 行档案丢给用户看——没人看得完,确认变成走过场。压成一张统计表后,用户 30 秒能扫完,确认才是真确认。它只活在对话里、不落盘,因为它是档案的「视图」而非数据:档案变了重新生成就行,落盘反而会产生两份会过期的真相
**写错会坏什么:** 摘要漏报「信息不足维度」,用户在不知情下放行了一锅薄料,垃圾进垃圾出,错误被后面三站逐级放大

### 检查点 2.5 提炼摘要(对话内产物)

**谁写它:** 主 agent,提炼完成后
**谁读它:** 用户——第二次暂停
**它管什么:** 提炼结果的清单视图:心智模型 N 个(列名字)、启发式 N 条、表达 DNA 关键特征、张力 N 对、边界 N 条
**它不管什么:** 不展开每个模型的论证细节,细节在 2.5 通过后才写进成品
**为什么长这样:** 提炼是全流程主观判断最重的一站,也是最后一个还便宜的回头点——skill 原文:「确认后再构建,避免写完400行SKILL.md才发现方向不对」。摘要只列名字不列论证,是为了让用户检查「方向」而不是陷进措辞
**写错会坏什么:** 摘要里模型名起得含糊(「营销思维」),用户看不出方向偏了,组装完才发现「这不是我要的孙宇晨」,返工整站

### [person]-perspective/SKILL.md(最终成品)

**谁写它:** 组装站,按 references/skill-template.md 的固定骨架填充
**谁读它:** 验证子 agent(三测试)、quality_check.py(机器检查)、最终用户(每次激活全量加载)
**它管什么:** 人物的完整认知操作系统:角色扮演规则、Agentic Protocol、心智模型(带证据和局限)、决策启发式、表达 DNA、内在张力、诚实边界、调研来源附录
**它不管什么:** 不内嵌调研原文——附录只引用 `references/research/` 的文件路径,证据链靠目录结构而不是复制粘贴
**为什么长这样:** 直觉形状是一段「你是孙宇晨,你很高调」的人设 prompt。模板把它换成了「操作系统」结构:模型带局限(防滥用)、协议带研究清单(防编数据)、边界独立成节(防过度信任)、附录指向档案(防口说无凭)。每个反直觉的节,都是一类失败的疫苗
**写错会坏什么:** 漏写诚实边界,用户把推测当事实引用;研究维度写成通用「搜索相关信息」,运行期协议名存实亡,回到编数据的老路

成品的最小单元长这样——一张带证据和局限的心智模型卡(来源:源包 sun-yuchen-perspective/SKILL.md,有删节):

```markdown
### 模型2: 叙事覆盖(Narrative Override)

**一句话**:不需要改变事实,只需要改变事实的定义。

**证据**:
- 白皮书抄袭以太坊 → 「翻译问题」→ 把抄袭重定义为「不够彻底的学习」
- 割韭菜指控 → 「教育成本必须计入商业模型」
- CNBC问SEC官司 → 直接聊「加密冬天是否结束」,把个人问题升维成行业问题

**局限**:面对硬证据(SEC 60万笔洗售交易的链上记录)时,叙事覆盖有天花板。
法庭不接受重新定义。最终还是花了1000万美元和解。
```

「证据」字段逼着每个模型至少两个真实场景背书——这是三重验证在成品里留下的形状;「局限」字段是 quality_check 的检查项之一,也是「诚实边界」精神在模型粒度的落点。少了哪个字段,这张卡就退化回一句口号。

### 验证与精炼报告(对话内产物)

**谁写它:** 验证子 agent(三测试结果)+ quality_check.py(六项检查输出)+ 双 Agent 精炼(两份改进建议)
**谁读它:** 主 agent(决定迭代还是交付)+ 用户(最终确认)
**它管什么:** 成品能不能交付的证据:已知立场对比、边缘问题分寸、100 字盲测、六项硬指标
**它不管什么:** 不直接改成品。报告归报告,改动由主 agent 应用,迭代上限 2 轮
**为什么长这样:** 验证产物和成品分离,是「验收权交给外人和机器」的实体形态:报告由独立来源写、主 agent 只能读。如果让验证 agent 直接改成品,独立性就没了——它会顺手把测试改到能通过
**写错会坏什么:** 报告只说「通过/不通过」不给样本,主 agent 没法定位回哪一站修;用户也失去了「展示验证结果给用户确认后才算完成」那一步的判断材料
