## 产物卡

### `references/research/0X-xxx.md`

**谁写它:** stage-03 的六个并行 subagent，各写一份
**谁读它:** stage-04 的 `merge_research.py`（统计）、stage-05 的提炼（原料）、最终成品的「调研来源」附录
**它管什么:** 一个维度的原始调研证据，每条带来源 URL 和可信度标记
**它不管什么:** 不管提炼判断——它只存证据，「哪条是真信念」是 stage-05 的事
**为什么长这样:** 六个文件而不是一个大文件，是因为单上下文查一个人必然偏科；切成互不重叠的六维、各自落盘，既能并行又逼着把「他者评价」「重大决策」这类容易跳过的维度也填满。文件名写死 `01-06`，是为了让 `merge_research.py` 能机器扫描。
**写错会坏什么:** 不落盘，调研等于没做，stage-05 没原料；不标一手/二手，提炼时分不清证据权重，容易把二手转述当真信念。

这是 `03-expression-dna.md` 的真实片段（标本）：

```text
**"insanely great"** | 最高级赞美，Mac 发布时的标志性用语
  → "insanely" 把 "great" 从正常赞美推到疯狂领域，传递的不是理性评估而是情感激动
[推断] 这个词库有一个显著 pattern：全部是绝对化表述，没有比较级。
来源：[Vocabulary.com](https://www.vocabulary.com/...)
```

`[一手]/[二手]/[推断]` 标记是可信度，URL 是溯源——少了任一个，后面的步骤就没法判断这条能不能用。

### `merge_research.py 摘要表`

**谁写它:** stage-04 的 `merge_research.py`
**谁读它:** 用户（在检查点拍板）、主 agent（决定哪维要补）
**它管什么:** 把六份调研的来源数、一手占比、关键发现、矛盾点压成一张可一眼扫的表
**它不管什么:** 不管对错判断——它只数数，不读懂内容
**为什么长这样:** 做成自动表是因为手工数六个文件又烦又错；但它用 URL 数当来源数、关键词命中数当一手占比，所以数值是近似信号而非精确指标——它的形状是「省力的粗筛」，不是「可信的度量」。
**写错会坏什么:** 把近似值当精确值，会误判调研质量——比如看到「决策 0 来源」就以为决策维度没查，其实只是没贴 URL。

这是它在 steve-jobs 上的真实输出（标本）：

```text
│ 决策          │ 0        │ 早期决策/被逐出 Apple…     │
│ 总来源数      │ 118      │ 一手占比: 134/244          │
```

「决策 0」和「134/244」都是脚本机制的产物，不是调研真相——读这张表要带着这个认知。

### `提炼结果（心智模型 / DNA / 边界）`

**谁写它:** stage-05 的主 agent
**谁读它:** 提炼确认检查点的用户、stage-06 的构建
**它管什么:** 通过三重验证筛出的 3-7 个心智模型、表达 DNA、内在张力、诚实边界——成品的全部骨料
**它不管什么:** 不管最终排版和角色扮演规则（那是模板的事）
**为什么长这样:** 它是「HOW they think」的结构化形式而不是金句清单，因为金句不能推断新立场；每个模型强制带「局限」字段，是为了防止写出只有优点的假人。
**写错会坏什么:** 把语录当模型，成品就是漫画式人设，遇到没收录的新问题就崩。

### `SKILL.md`（最终产物）

**谁写它:** stage-06 的构建，套 `skill-template.md`
**谁读它:** stage-07 的独立子 agent 和 `quality_check.py`、最终用户
**它管什么:** 一个可直接激活的人物思维操作系统：角色扮演规则、心智模型、Agentic Protocol、表达 DNA、诚实边界
**它不管什么:** 不管调研过程（留在 `references/research/`）——成品只装结论，过程可溯源但不塞进正文
**为什么长这样:** 它把「先做功课再开口」的 Agentic Protocol 放在角色规则之后、示例之前，是因为人物 skill 最大的失败模式就是凭训练语料编。研究维度按心智模型定制而不套通用清单，则是因为通用搜索抓不到这个人真正会看的东西。
**写错会坏什么:** 漏掉 Agentic Protocol，成品遇到事实问题就编；研究维度套通用模板，成品「查了也白查」。

成品里「模型1」的真实形态（标本）：

```text
### 模型1: 聚焦即说不（Focus = Saying No）
一句话：聚焦不是对你要做的事说 Yes，而是对其他一百个好主意说 No。
局限：我曾经对第三方 App 说 No（2007），一年后不得不 180 度大转弯开放 App Store。
```

「局限」字段里装的是本人打脸的真实案例——这正是「不写只有优点的假人」要的东西。

### `quality_check.py 输出`

**谁写它:** stage-07 的 `quality_check.py`
**谁读它:** 主 agent（决定是否回炉）
**它管什么:** 六项硬标准的 PASS/FAIL 快检：模型数量、局限性、表达 DNA、诚实边界、内在张力、一手占比
**它不管什么:** 不管「像不像本人」——那是独立子 agent 的盲读测试管的
**为什么长这样:** 做成廉价正则快检，是为了在派子 agent 做贵的语义测试之前先挡掉明显不合格的；代价是它会误报，比如把 `1.` 编号的诚实边界数成 0 条。
**写错会坏什么:** 把脚本的 PASS 当成「可交付」，会漏掉只有机器测不出的 AI 味——脚本是 gate 的一半，另一半必须是独立子 agent。
