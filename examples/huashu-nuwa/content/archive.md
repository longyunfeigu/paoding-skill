## 卡片

### A1 心智模型而非金句 · 维度：领域-认知

**症状:** 你问成品「我在做折叠屏手机，乔布斯会怎么看」，它答「要专注、要极致、不要为技术而技术」——每个字都对，但你换成「马斯克会怎么看」答案几乎一样，它只是把名言重排了一遍（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 中间产物是「专注就是说不」等金句清单 | 中间产物是「面对资源分配先问该砍什么」的可运行模型 |

**Therefore:** 金句只能背，心智模型能拿去算一道它没见过的新题。

**机制原文:**

> **关键区分**：捕捉的是HOW they think，不是WHAT they said。

把中间产物从「他说过的话」换成「他思考的方式」，再用三重验证（stage-05）筛掉场面话——这样成品面对新问题时有模型可推，而不是有名言可背。

**机制说明:** 这是整个 skill 的认知地基，决定了为什么要六维取证、为什么提炼是筛而不是抄。
**解法层次:** 表征解法
**可迁移性:** 高
**什么时候用:** 任何「把一个人或一套方法提炼成可复用能力」的建模任务。
**什么时候太重:** 只需要应景贴几句名人名言做装饰时，三重验证是杀鸡用牛刀。
**反例:** 做一张励志海报，要的就是金句本身，不需要可运行模型。
**在哪几个 skill 里见过:** 女娲全部 15 个示例；任何角色扮演 / 思维顾问类 skill。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 做思维顾问 skill | 管用 | 模型能推断新立场，这是甜区 |
| 一次性玩梗角色扮演 | 可以简化 | 几句口癖就够，不必炼模型 |
| 贴名言做装饰 | 用不上 | 要的就是金句本身 |

**一起读:**
- A3 六维并行取证（前置：模型的原料靠它供）
- A2 先查再答（搭配用：模型负责想得像，协议负责做得像）

### A2 Agentic Protocol 先查再答 · 维度：行为

**症状:** 你问成品「乔布斯会怎么评价 Vision Pro」，它流畅地引用几个「乔布斯说过」的观点给出判断——可乔布斯 2011 年就走了，Vision Pro 是 2024 年的，它在用旧语料编，而你看不出来（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 遇到事实问题直接凭训练语料答 | 判定为「需要事实」→ 先 WebSearch 再用框架答 |

**Therefore:** 让人物「说得像」不够，得逼它「做得像」——先做功课再开口。

**机制原文:**

> 没有这个段落，人物Skill遇到需要事实的问题时会凭训练语料编造，而不是像真人一样先做功课再发言。

成品里装一段三步工作流，进来先把问题分成「需要事实 / 纯框架 / 混合」三类，需要事实的强制先搜——这道分流挡住的就是「凭旧记忆编」。

**机制说明:** 研究维度按心智模型定制（乔布斯看产品体验，芒格看激励结构），通用搜索清单抓不到这个人真正会看的东西。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何怕模型编造、需要「先取事实再下判断」的角色 agent。
**什么时候太重:** 纯抽象哲学问答（「什么是聚焦」）不需要先搜，强行搜反而拖慢。
**反例:** 一个故意只玩文风的诗歌模仿 bot，不需要事实，装协议是负担。
**在哪几个 skill 里见过:** 女娲的 munger / steve-jobs / mrbeast 示例都现推了不同研究维度；任何 RAG / 工具调用 agent。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 评价具体产品/公司 | 管用 | 强制取最新事实，挡住编造 |
| 抽象理念问答 | 不用做 | 纯框架题跳过研究 |
| 离线无工具环境 | 用不上 | 没法搜，只能退回框架 |

**一起读:**
- A1 心智模型而非金句（搭配用：模型供判断，协议供事实）
- A5 入口分流（对照：都是「先分类再行动」的同一手法）

### A3 六维并行取证 + 必落盘 · 维度：编排

**症状:** 单个 agent 从头查一个人，读到几篇精彩演讲分析就停不下来，最后 `01-writings.md` 写得很厚，`05-decisions.md` 和 `04-external-views.md` 几乎是空的，人设单薄偏科（证据：结构推断）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 一个上下文查到底，维度厚薄随兴趣漂 | 六维各派一独立 agent，各自落盘成 `01-06.md` |

**Therefore:** 一个上下文装不下一个完整的人，切成互不重叠的六维才不偏科。

**机制原文:**

> 启动6个并行subagent，每个负责不同信息维度。
> 每个subagent必须把调研结果写入对应的md文件。不存文件的调研等于没做。

六个维度互不重叠，天然不撞车；落盘硬令逼着每个 agent 把发现写下来，而不是烂在自己上下文里——并行解决偏科，落盘解决「查了等于没查」。

**机制说明:** 文件名写死 `01-06`，是为了让 `merge_research.py` 能机器扫描统计。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何单上下文会偏科、需要多 agent 协作产出的调研类任务。
**什么时候太重:** 调研对象很小（一篇博客、一次访谈），六维属于过度切分。
**反例:** 只需快速查一个事实，派六个 agent 是仪式感。
**在哪几个 skill 里见过:** 女娲全部带 `research/01-06.md` 的示例；任何 deep-research / 多源调研 skill。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 给一个公众人物建全画像 | 管用 | 六维互补，逼着填满冷门维度 |
| 蒸馏只有一本书的冷门人 | 得让一步 | 维度合并，别硬撑六个 agent |
| 查一条事实 | 没必要 | 一个 agent 足够 |

**一起读:**
- A4 调研/提炼双检查点（下游接管：六份调研的质量由它来验）
- A9 信息源黑名单（搭配用：并行采集时统一选源标准）

### A4 调研 / 提炼双检查点 · 维度：行为

**症状:** 默认 agent 调研一回来就埋头提炼，写到第 300 行 SKILL.md 才发现「他者视角」那一栏全是营销稿，方向错了，整段推倒重查（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 调研完直接写到底 | 调研后暂停展示摘要，用户确认才往下 |

**Therefore:** 上一段质量决定下一段上限，把返工提前到最便宜的那一步。

**机制原文:**

> **所有Agent完成后，暂停展示调研质量摘要**
> 这个检查点的意义：调研质量决定了最终Skill的上限。垃圾进垃圾出，在这里拦截比在Phase 4返工成本低得多。

在调研和提炼之间、提炼和构建之间各插一道暂停门，把上一段产出量化成摘要让用户拍板——挡住的是「带病往下走、最后才发现源头错」。

**机制说明:** Phase 1.5 用 `merge_research.py` 出摘要表，Phase 2.5 展示提炼结果摘要。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何上一段质量决定下游上限的多阶段流程（调研、清洗、需求确认）。
**什么时候太重:** 一次性短任务没有「下游」，插检查点只是打断节奏。
**反例:** 改个错别字也要先暂停确认，是仪式。
**在哪几个 skill 里见过:** 女娲；很多带「计划/确认」阶段的 pipeline skill。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 多阶段、阶段质量传递 | 管用 | 返工提前，省下最贵的重写 |
| 用户不在场的全自动跑 | 得让一步 | 没人拍板，只能 agent 自检代替 |
| 单步小任务 | 不用做 | 没有下游可污染 |

**一起读:**
- A3 六维并行取证（前置：它验的就是这步的产出）
- A6 独立子 agent 验证（区别于：这里是用户拍板，那里是独立 agent 当裁判）

### A5 入口分流 · 维度：需求

**症状:** 用户说「我想提升决策质量」，默认 agent 要么反问「那你想蒸馏谁」把皮球踢回去，要么自作主张挑了个塔勒布，结果用户要的是商业决策不是风险对冲，整条流水线白跑（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 对模糊需求直接开搜或反问「蒸馏谁」 | 先分流，用需求维度表反推 2-3 个候选让用户选 |

**Therefore:** 用户给的常是模糊需求，猜错对象比多问一句贵得多。

**机制原文:**

> | 用户输入 | 路径 | 示例 |
> | --- | --- | --- |
> | 明确的人名/主题 | **直接路径** → Phase 0A | 「蒸馏芒格」 |
> | 模糊的需求/困惑 | **诊断路径** → Phase 0B | 「我想提升决策质量」 |

进门先判断输入类型：明确人名直接做，模糊需求走诊断、用需求维度表把困惑翻成候选人物——挡住的是「对着错对象做完一整轮」。

**机制说明:** 诊断路径限「最多问 2 轮」，避免把澄清做成问卷。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何用户输入可能是「明确目标」也可能是「模糊困惑」的 skill 入口。
**什么时候太重:** 输入永远是结构化的（比如只接受人名 ID）时，分流多余。
**反例:** 一个只处理「翻译这段」的工具，输入无歧义，不需要分流。
**在哪几个 skill 里见过:** 女娲；很多带「澄清/对齐」开场的 skill。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 入口可能模糊 | 管用 | 猜错代价高，分流最划算 |
| 输入永远是人名 | 没必要 | 没有歧义可分 |
| 用户自己也没想清 | 看情况 | 诊断能帮收敛，但别问超 2 轮 |

**一起读:**
- A2 先查再答（对照：同是「先分类再行动」）
- A7 信息不足就降级（下游接管：选定对象后若来源太少，转入降级）

### A6 独立子 agent + 盲读认人 · 维度：品味

**症状:** 主 agent 写完自己读一遍，觉得「挺像乔布斯，可以交付」；可把名字遮掉给旁人读 100 字，对方认不出是谁，满屏是「追求卓越、拥抱变化」式通用鸡汤（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 主 agent 自评「像不像」 | 独立子 agent 盲读 100 字判断能否认出是谁 |

**Therefore:** 作者对自己的字脸盲，验收必须换一个没下过笔的裁判。

**机制原文:**

> 用子agent执行3项测试（独立于主agent，避免自评偏差）
> 用Skill写一段100字分析，判断：有此人的表达特征？不是通用AI味鸡汤？

把「像不像」这种说不清的标准交给独立子 agent，用盲读认人的可判测试——挡住的是「作者自评放水」。

**机制说明:** 配一张通过标准表把「好」量化（读 100 字能认出是谁 / 像通用 ChatGPT = 不通过）。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何验收标准是「像不像 / 好不好」这种主观项、且作者会自评放水的场景。
**什么时候太重:** 有明确客观指标（编译过 / 测试绿）时，不必再派独立裁判。
**反例:** 单元测试能判对错的代码，不需要盲读裁判。
**在哪几个 skill 里见过:** 女娲 Phase 4/5；庖丁自己的 voice gate 也强制独立 subagent，同一手法。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 验「像不像某人」 | 管用 | 盲读认人把主观项变可判 |
| 有客观指标的产物 | 用不上 | 测试绿就够，不必盲读 |
| 没有第二个 agent 可用 | 得让一步 | 退回作者自查，但要清单驱动 |

**一起读:**
- A4 调研/提炼双检查点（区别于：那里用户拍板，这里独立 agent 当裁判）
- A1 心智模型而非金句（搭配用：盲读认人正是在验模型有没有炼出辨识度）

### A7 信息不足就降级 · 维度：品味

**症状:** 蒸馏一个冷门人物，全网只翻到 5 条可用来源，默认 agent 仍然写出 7 个「深刻」的心智模型，看着完整其实大半是编的（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 来源再少也写满 7 个模型 | 来源 <10 就降到 2-3 个模型，加大诚实边界篇幅 |

**Therefore:** 宁要一个诚实标注局限的 60 分，不要一个看着完美实则编造的 90 分。

**机制原文:**

> 宁可生成一个诚实标注了局限的60分Skill，也不要生成一个看起来完美但实际上在编造的90分Skill。

来源不足时主动降低模型数、加大诚实边界篇幅、标注「基于有限信息推测」——挡住的是「用编造把空缺填满」。

**机制说明:** 矛盾信息不抹平，保留为「内在张力」，本身就是有价值的信号。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何「素材可能不足、但仍要交付」的生成任务。
**什么时候太重:** 素材极其充足时，这条只是提醒，不构成约束。
**反例:** 数据完备的报表生成，不存在「信息不足」分支。
**在哪几个 skill 里见过:** 女娲冷门人物分支；任何怕「自信地胡编」的研究 skill。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 冷门人物/稀缺素材 | 管用 | 用降级换诚实，挡住编造 |
| 素材极充足 | 可以松点 | 约束基本不触发 |
| 用户明确只要「看起来完整」 | 反而碍事 | 与用户的（坏）目标冲突 |

**一起读:**
- A5 入口分流（前置：选定对象后才发现来源不足，转入降级）
- A2 先查再答（搭配用：都是「不确定就别硬编」的同一价值观）

### A8 字幕脚本（下载 + 清洗） · 维度：领域-工程

**症状:** 拿一段 YouTube 演讲做语料，手动复制字幕，结果满屏 `00:00:12,340 --> 00:00:15,200` 时间戳和自动字幕的连续重复行，喂给模型全是噪声（证据：结构推断）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 手抄字幕，时间戳/重复行污染语料 | 脚本取字幕 + 去时间戳去重分段成干净 transcript |

**Therefore:** 易错的机械活交给脚本，agent 只读干净文本。

**机制原文:**

> **Step 1 下载字幕**：`bash scripts/download_subtitles.sh <YouTube_URL>`（自动优先人工字幕 → 中文 → 英文 → 自动生成字幕）
> **Step 2 清洗为纯文本**：`python3 scripts/srt_to_transcript.py <input.srt>`（去时间戳、序号、HTML标签、连续重复行）

下载脚本按四级 fallback 拿到最优字幕，清洗脚本去掉时间戳和重复行再分段——挡住的是「人手清洗又烦又漏」。

**机制说明:** 清洗按 200 字或句末标点重新分段，输出可直接阅读的 transcript。
**解法层次:** 脚本解法
**可迁移性:** 高
**什么时候用:** 任何要把视频/播客字幕变成干净语料的调研任务。
**什么时候太重:** 只有文字素材时这两个脚本用不上。
**反例:** 处理一段已经干净的纯文本，跑清洗脚本是空转。
**在哪几个 skill 里见过:** 女娲；任何处理字幕/transcript 的内容 skill。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 视频/播客做语料 | 管用 | 替你干掉清洗杂活 |
| 纯文本素材 | 用不上 | 没有字幕要清 |
| 字幕已是干净文本 | 没必要 | 清洗空转 |

**一起读:**
- A3 六维并行取证（搭配用：清洗后的 transcript 是采集的原料）
- A9 信息源黑名单（搭配用：都是「采集阶段的工程约束」）

### A9 信息源黑名单 · 维度：品味

**症状:** 蒸馏一个中国企业家，agent 顺手大段引用知乎高赞答案和百度百科，里面混着洗稿和过时信息，焊进人设后再难拆出来（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 搜到就用，知乎/百科一并入库 | 知乎/公众号/百度永久排除，只收权威媒体 |

**Therefore:** 有些来源默认就会污染人设，与其事后筛不如事前拉黑。

**机制原文:**

> #### 信息源黑名单（永远排除）
> - **知乎**：洗稿严重、信息失真率高
> - **微信公众号**：封闭生态、无法验证
> 中文渠道只接受权威媒体：36氪、极客公园、晚点LatePost、财新…

把三类低质来源写死成永久黑名单，配一张一手 > 二手的优先级表——挡住的是「用失真来源喂人设」。

**机制说明:** 中国人物和西方人物的来源池不同，B 站原视频和小宇宙原始音频优先。
**解法层次:** 表征解法
**可迁移性:** 高
**什么时候用:** 任何中文人物 / 主题调研的选源。
**什么时候太重:** 调研对象只有英文资料时，这张中文黑名单用不上。

### A10 merge_research 浅统计 · 维度：领域-工程

**症状:** `merge_research.py` 跑 steve-jobs 报「决策 0 来源」「一手占比 134/244」——决策档案明明写满四段决策，只是没贴 URL，脚本拿 URL 数当来源数就报了 0（证据：实测）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 手工点开六个文件数来源，又烦又错 | 脚本一键出摘要表，但读数是近似 |

**Therefore:** 脚本省了你点文件的力气，但近似读数这一步还得人脑覆盖。

**机制原文:**

> # 计算URL数量作为来源数
> urls = re.findall(r'https?://[^\s\)]+', content)
> primary_markers = len(re.findall(r'一手|primary|本人|原文', content))

它用 URL 数估来源、用关键词命中数估一手占比——这是廉价快检的实现代价：省力但失真，所以「决策 0」是脚本机制的产物，不是调研真相。

**机制说明:** 同样的浅检查也出现在 `quality_check.py`：它只数 `-`/`*` 项目符号，把芒格成品里 `1.` 编号的 6 条诚实边界误报成 0 条 FAIL。
**解法层次:** 脚本解法
**可迁移性:** 低
**不可迁移原因:** 缺第二个佐证案例——这是这两个脚本特有的近似实现，换个任务要重写。可带走的是「脚本快检会失真、读数要人覆盖」这条认知，已在 stage-04 标为可偷。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 快速扫六个文件有没有写 | 管用 | 比手点省力 |
| 当精确质量度量用 | 反而碍事 | 近似值会误导判断 |
| 文件不贴 URL/不用项目符号 | 用不上 | 统计口径直接落空 |

**一起读:**
- A4 调研/提炼双检查点（下游接管：它是检查点的物料生成器）
- A6 独立子 agent 验证（对照：机器快检会误报，真裁判还得是独立 agent）

## 残渣与砍掉候选

### Phase 5 双 Agent 精炼
**判定:** 过度设计
**理由:** Phase 4 已用独立子 agent 做了三测试验证，Phase 5 再加一轮「auto-skill-optimizer 视角 + skill-creator 视角」的双 agent 评审，与 Phase 4 的边界重叠；而且它点名的两个视角对应外部 skill，包里并无这两个 agent 的定义，更像借了名字。价值真实，但属于「能砍到 Phase 4 里」的候选。

### merge_research.py 的一手占比算法
**判定:** 过度设计
**理由:** 用关键词命中数估一手/二手占比，输出 134/244 这种不可解读的数；便利件做成了看似精确实则误导的指标，不如直接不报这一栏。

### download_subtitles.sh 的 /tmp/.ytdlp_marker
**判定:** 平台伤疤
**理由:** 第一条 fallback 用 `find -newer /tmp/.ytdlp_marker` 比对一个从未创建的 marker 文件，判断不可靠；是没擦干净的小 bug。

## 盲区

- 三重验证全靠主观判断，没有任何机器门能拦住一个「听起来深刻其实是套话」的心智模型。
- 「过度模仿变 caricature」只在质量自检清单里提了一句，没有强制机制。
- `quality_check.py` 的一手占比检查在「未标记来源类型」时直接跳过，很多成品就不标，这道门形同虚设。
- 建议用 Z-Library/LibGen 下书，法律灰色地带，skill 未提示版权风险。
- 蒸馏活人可能做出有偏差的人设，带来名誉/隐私风险；诚实边界提了「公开 vs 真实想法有差距」，但没防误用。
