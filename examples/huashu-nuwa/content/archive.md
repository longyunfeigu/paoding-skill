## 卡片

### A1 先取证再提炼,不许凭记忆写人设 · 维度：领域-认知

**症状:** 你问语录拼贴版「乔布斯」:「Vision Pro 现在值不值得做?」它答:「人们不知道自己想要什么,直到你把它放到他们面前。值得做。」——流畅、像他,但没查任何事实,是用旧语料编的,而且你看不出来。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 人设直接从训练记忆生成:「我的名言:The future is bright。我的性格:自信高调。」 | 动笔前必须先有 6 份落盘调研档案;人设的每个心智模型都标注「证据:≥2 个不同场景的引用」 |

**Therefore:** 把「写人设」从一步拆成两步——先用六个维度取证,动笔时只许引用取证结果。

**机制原文:**

> 启动6个并行subagent,每个负责不同信息维度。……区分「他说过的」vs「别人说他的」vs「我推断的」。发现矛盾时保留矛盾,不要和稀泥。

六个维度(著作/对话/表达/他者/决策/时间线)是对「一个人的公开痕迹」的完整切分;「区分三种话」直接堵住凭记忆混写的口子。

**机制说明:** 取证档案成为人设和现实之间的中间层:人设写什么,必须能在档案里指出处。这是「中间产物换形状」的典型——把不可校验的「记忆」换成可校验的「档案」。
**解法层次:** 表征解法
**可迁移性:** 高
**什么时候用:** 任何「让 AI 模仿/复刻一个具体对象」的任务——人物、品牌声音、代码风格,都先取证后生成。
**什么时候太重:** 对象的全部信息本来就在一份文档里(比如模仿一份风格指南),六路并行取证是杀鸡用牛刀,一路就够。
**反例:** 「先搜索再回答」的普通检索增强不是这招——这招的要点是取证结果落盘成档案、按维度分仓、被下游引用,不是搜完即弃。
**在哪几个 skill 里见过:** nuwa-skill;它的灵感源 colleague-skill(蒸馏同事)是同构做法。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 公开信息丰富的名人 | 管用 | 六个维度都有料,档案越厚镜片越准 |
| 冷门人物(来源<10条) | 得让一步 | 六路里几路会空转,skill 自己也降级到 2-3 个模型 |
| 模仿一份已成文的风格指南 | 用不上 | 证据已经集中成文,不需要再取证 |

**一起读:**
- A2 三重验证当收录门槛（下游接管：取证管「料真」,三重验证管「筛严」）
- A11 给人设装 Agentic Protocol（对照：A1 管「造人时不编」,A11 管「人造好之后回答时不编」）

### A2 三重验证当收录门槛 · 维度：领域-认知

**症状:** 人设的「核心心智模型」里赫然一条「拥抱变化」——他确实在某次年会说过,但任何 CEO 都会说。拿这副「镜片」看新问题,推出来的全是普通道理,一点不「他」。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 年会金句「拥抱变化」直接列为心智模型 | 「拥抱变化」只在 1 个场景出现、人人都会说 → 0 重通过,不纳入;「注意力套利」跨午餐/香蕉/政治献金三域复现 → 收录 |

**Therefore:** 给「算不算他的思维框架」立三道能淘汰东西的筛,筛不过的降级或丢弃。

**机制原文:**

> 验证1: 跨域复现——同一个思维框架出现在此人讨论的至少2个不同领域。
> 验证2: 有生成力——用这个模型可以推断此人对新问题的可能立场。
> 验证3: 有排他性——不是所有聪明人都会这样想。
>
> **如果一个观点只通过了1重验证** → 降级为「决策启发式」而非「心智模型」
> **如果一个观点0重验证都没过** → 可能只是此人在特定场景说的话,不纳入

三道筛分别砍掉三种噪音:偶发言论(跨域)、没有预测力的标签(生成力)、普世正确的废话(排他性)。降级通道保证「没过筛但有用」的信息不被扔掉。

**机制说明:** 这是中间产物的准入标准:心智模型区只收三重全过的,门槛本身写进了产物定义。
**解法层次:** 表征解法
**可迁移性:** 高
**什么时候用:** 任何「从大量素材里提炼少量核心」的任务:用户画像、品牌原则、设计价值观。
**什么时候太重:** 素材本来就稀薄时,三重筛会筛到空——女娲对冷门人物的对策是把模型数砍到 2-3 个并标注推测,而不是降低筛子标准。
**反例:** 「多找几个来源交叉验证」不是这招——那验的是出处数量;三重验证验的是观点的结构属性:跨域、有预测力、有区分度。
**在哪几个 skill 里见过:** nuwa-skill;各类带评分准入的提炼型 skill 是近亲。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 语料丰富的公众人物 | 管用 | 候选多,筛子有的淘汰 |
| 冷门人物 | 得让一步 | 筛剩 2-3 个,靠诚实边界补 |
| 主题 skill(提炼领域方法论) | 看情况 | 排他性要换成「流派区分度」,标准要改写 |

**一起读:**
- A1 先取证再提炼,不许凭记忆写人设（前置：档案先有料,筛子才有对象）
- A5 矛盾保留为张力（搭配用：筛出来的矛盾不调和,单独成节）

### A3 调研不落盘等于没做 · 维度：编排

**症状:** 六路调研在各自对话里汇报,主 agent 聚合时上下文装不下,表达 DNA 那一路的发现只剩两行进了成品;附录想给「调研来源」留链接,无处可指。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 子 agent 在对话末尾输出长汇报,主 agent 摘要的摘要进成品 | 每路写入开工前定死的 `01-06.md`,聚合按文件读,附录永久引用文件 |

**Therefore:** 把 agent 之间的交接从「对话」改成「文件」,文件名在开工前分配,文件位置锁死在交付目录内部。

**机制原文:**

> 每个subagent必须把调研结果写入对应的md文件。不存文件的调研等于没做。
>
> **所有调研文件必须存在skill目录内部**(`references/research/`),绝对不要存到 `07-调研与分析/` 或其他外部目录。Skill必须是自包含的——复制整个skill目录就能独立使用,不依赖任何外部文件。

第一句解决「对话交接丢素材」;第二句解决「分发后断链」——禁令具体到 `07-调研与分析/` 这个目录名,是踩过坑的疤痕。

**机制说明:** 两条规则合起来,把多 agent 协作的协调成本压到最低:文件名即接口,目录即交付边界。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何多 agent 并行产出要被下游消费的编排,尤其产物将来要打包分发时。
**什么时候太重:** 单 agent 的一次性小任务,落盘成了仪式负担。
**反例:** 「让子 agent 输出结构化 JSON」不是这招——结构化解决的是解析;这招解决的是把产物写成文件留下来:路径预先定好,后面的步骤直接按文件名引用,引用不出包。
**在哪几个 skill 里见过:** nuwa-skill;庖丁手册生产流程的 content/ 分文件并行写作是同构。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 6 路并行、产物要分发 | 管用 | 协调零成本,交付自包含 |
| 两个 agent 的短流水 | 可以松点 | 一份共享文件就够,不必六仓分立 |
| 单体小任务 | 没必要 | 没有交接,落盘只是开销 |

**一起读:**
- A8 检查点设在错误放大之前（搭配用：落盘的档案是检查点能验料的前提）
- A12 字幕获取交给脚本回退链（搭配用：脚本产物同样落盘进 sources/）

### A4 信息源黑名单 · 维度：领域-工程

**症状:** 人设张口就是「马云在湖畔大学说过 XX」——出处是知乎洗稿文,本人从未说过。用户拿着这句去引用,在公开场合翻车。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 搜到什么用什么,知乎高赞回答进调研档案 | 知乎/公众号/百度百科永远排除;中文只收 36氪、晚点、财新等权威媒体和 B站原始视频、小宇宙原始音频 |

**Therefore:** 与其事后逐条甄别,不如把失真率高的渠道整体拉黑——按渠道治理比按内容治理便宜得多。

**机制原文:**

> - **知乎**:洗稿严重、信息失真率高,不作为任何维度的来源
> - **微信公众号**:封闭生态、无法验证、大量二手转述,不作为来源
>
> 中文渠道只接受权威媒体……人物访谈类可用播客平台(小宇宙、喜马拉雅原始音频)和B站原始视频(非搬运号)。

黑名单是硬排除;配套的信息源权重表(用户一手素材 > 本人著作 > 长对话 > 社交媒体 > 二手转述)处理「同一信息多个来源信谁」。

**机制说明:** 每条黑名单都附带理由(洗稿/无法验证/陈旧),不是品味偏见,是失真率判断。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何依赖公开网络信息的调研任务,尤其中文信息生态。
**什么时候太重:** 小众话题的唯一讨论恰好都在黑名单渠道里(某些垂直社区只活跃在知乎)——一刀切会饿死调研,这时该降级处理而不是直接放行。
**反例:** 「优先权威来源」的软排序不是这招——软排序里坏渠道仍可垫底入册;黑名单是硬排除,根本不入册。
**在哪几个 skill 里见过:** nuwa-skill;调研类 skill 常见同构的渠道白/黑名单。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 公众人物的中文调研 | 管用 | 洗稿渠道密度高,硬排除收益大 |
| 只有社区讨论的小众对象 | 得让一步 | 黑名单渠道可能是唯一来源,需降级使用并标注 |
| 英文人物 | 用不上 | 黑名单全是中文渠道;英文生态要另建名单 |

**一起读:**
- A1 先取证再提炼,不许凭记忆写人设（搭配用：黑名单保证档案里的料干净）
- A6 60 分诚实优于 90 分编造（搭配用：料被黑名单筛少了,宁缺毋滥）

### A5 矛盾保留为张力 · 维度：领域-认知

**症状:** 人设的价值观高度自洽:「我崇尚去中心化。」追问 Steem 接管事件(他用交易所代币投票夺权),它要么失忆、要么现编一个圆场解释——一听就假。女娲的质检表把这个写成了不通过信号:「观点高度一致(太假)」。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 「他表面高调,内心其实注重长期价值」(编出来的调和解释) | 「去中心化布道者 vs 中心化控制者:嘴上说去中心化,实际同时控制公链+交易所+大量代币」(原样保留进「内在张力」节) |

**Therefore:** 矛盾不是数据清洗对象,是人格深度的原料——在成品里单独给它留一节,而不是抹平它。

**机制原文:**

> 矛盾是人格的核心特征,不是需要修复的Bug。
>
> ### 错误的处理方式
> - ❌ 选一边忽略另一边
> - ❌ 编一个调和的解释
> - ❌ 假装矛盾不存在

配套的三分类(观点演化/分场景双标/价值观内在冲突)决定每种矛盾的归置:演化标注「早期/近期」,双标分领域记录,本质张力直接进成品。

**机制说明:** 质检端还反向加压:内在张力少于 2 对不许交付。整条流水线在结构上奖励「保留矛盾」。
**解法层次:** 表征解法
**可迁移性:** 高
**什么时候用:** 提炼任何真实对象(人物、组织文化、产品哲学)时撞上自相矛盾的证据。
**什么时候太重:** 矛盾其实是数据错误(两个来源把日期记反了)时,该核实订正,不该供奉成张力。
**反例:** 「正反观点都列一下」的骑墙不是这招——张力是「他同时真心持有两边」,必须写出冲突发生的具体场景(如 Steem 事件),不是各打五十大板。
**在哪几个 skill 里见过:** nuwa-skill。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 言行复杂的争议人物 | 管用 | 张力密度高,是人设深度的主要来源 |
| 立场单一的专业学者 | 得让一步 | 真张力可能确实少,硬凑 2 对反而假 |
| 主题 skill | 看情况 | 张力换形态:变成「流派间的根本分歧」 |

**一起读:**
- A2 三重验证当收录门槛（前置：先筛出真信念,矛盾才有分量）
- A10 表达 DNA 量化+语气校准锚点（搭配用：张力和声纹共同构成辨识度）

### A6 60 分诚实优于 90 分编造 · 维度：行为

**症状:** 蒸馏一个只有 8 条公开报道的冷门创业者,默认 agent 照样交出「7 个心智模型」——全部从 3 篇通稿外推,看起来完整丰满,实际是模板化编造,而且不留任何「这是猜的」标记。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 信息稀薄,模板照样填满 | 来源<10条 → 模型砍到 2-3 个、每个标注「基于有限信息推测」、诚实边界扩容、提前告知用户 |

**Therefore:** 把「信息不足」从隐性风险变成显性的降级开关:少料就少产出、多标注,并且提前说。

**机制原文:**

> **关键规则**:宁可生成一个诚实标注了局限的60分Skill,也不要生成一个看起来完美但实际上在编造的90分Skill。

配套的信息不足处理表给了细则:「某个维度公开信息很少 → 标注『信息不足,此维度为推测』」「只有二手信息 → 降低置信度,标注『据[来源]报道』」「此人刻意不公开某方面 → 尊重边界」。

**机制说明:** 降级是结构性的——改变产出的规模(模型数)和形状(边界篇幅),不是在末尾贴一句免责声明。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何输入质量不可控的生成任务:调研、画像、报告。
**什么时候太重:** 输入质量有保证的封闭流水线(料永远充足),降级分支永不触发,是死代码。
**反例:** 在产出末尾统一加「仅供参考」不是这招——降级必须真的改变产出(砍模型数、扩边界),免责标签改变不了编造本身。
**在哪几个 skill 里见过:** nuwa-skill;「评估置信度→调整交付规模」在严肃调研类 skill 里是通用形。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 冷门人物 | 管用 | 这是开关存在的全部意义 |
| 信息丰富的名人 | 不用做 | 开关不触发,零成本 |
| 用户提供完整一手语料 | 用不上 | 料的质量已被用户锁定,不存在「不足」判断 |

**一起读:**
- A4 信息源黑名单（搭配用：黑名单筛掉坏料后,料少了就触发这个开关）
- A7 验收权交给外人和机器（下游接管：「诚实边界≥3条」是质检硬指标）

### A7 验收权交给外人和机器 · 维度：行为

**症状:** 主 agent 写完自检:「质量很好,六项全部通过,可以交付。」换个人读它产出的 100 字,完全认不出在模仿谁——打分者和被打分者共享同一套盲区,验证环节形同虚设。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 生成者自己通读打分:「不错,通过」 | spawn 独立子 agent 跑已知/边缘/风格三测试;quality_check.py 数模型个数、边界条数、张力对数 |

**Therefore:** 验收拆成两半:品味类盲测交给独立子 agent,可数的标准交给脚本——两边都不经过生成者的手。

**机制原文:**

> 生成Skill后,用子agent执行3项测试(独立于主agent,避免自评偏差):
>
> #### 4.2 边缘测试(Edge Case)
> 选1个此人没公开讨论过但相关的问题,用Skill推断。
> - 期望结果:「基于模型X和Y的推断,可能...但不确定」
> - 不应该斩钉截铁

边缘测试的期望值设计得很妙:测的不是答对,是分寸——没聊过的问题敢斩钉截铁,说明在复读而不是推理。

**机制说明:** 配套的克制:迭代上限 2 轮,不过的项写进诚实边界交付,防止验收变成无限打磨。另一个注意:机器半边很脆(实测见残渣清单),脚本规则需要跟着产物格式维护。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 一切「生成和验收由同一个 agent 完成」的流程。
**什么时候太重:** 产出极小(一段文案)时,spawn 子 agent 的成本超过直接返工。
**反例:** 「我再仔细检查一遍」不是这招——自查无论多仔细,盲区是共享的;要点是验收者独立。
**在哪几个 skill 里见过:** nuwa-skill(Phase 4/5);庖丁手册的独立审稿门是同构。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 几百行的长成品 | 管用 | 返工成本高,独立验收的开销划算 |
| 一段短文案 | 用力过了 | 子 agent 开销超过返工本身 |
| 纯结构化产出(可全量机器检查) | 可以简化 | 留脚本,省掉子 agent 盲测 |

**一起读:**
- A6 60 分诚实优于 90 分编造（前置：验收标准里的「边界≥3条」由它供料）
- A8 检查点设在错误放大之前（区别于：检查点是中途人工对齐,这张卡是末端独立验收）

### A8 检查点设在错误放大之前 · 维度：编排

**症状:** 流程一口气跑到底,用户第一次看到产出已经是 400 多行的成品,一句「方向不对」让调研、提炼、组装全部重来。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 全自动跑完六站才见用户 | 调研后(1.5)和提炼后(2.5)各停一次,摘要给用户,点头才继续 |

**Therefore:** 人工确认不均匀撒、不放最后,专门插在「下一站会放大本站错误」的关口。

**机制原文:**

> 这个检查点的意义:调研质量决定了最终Skill的上限。垃圾进垃圾出,在这里拦截比在Phase 4返工成本低得多。
>
> 这个检查点的意义:提炼是主观判断最重的环节,确认后再构建,避免写完400行SKILL.md才发现方向不对。

两个检查点各自的「为什么停在这」都写明了:1.5 拦原料,2.5 拦方向。六站只停这两次。

**机制说明:** 检查点配了降低确认成本的工具:merge_research.py 自动生成摘要表,用户看统计不看原文。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 流水线里存在「主观判断重、下游放大效应强」的环节时。
**什么时候太重:** 短流程或重跑便宜的任务——暂停的交互成本超过返工成本。
**反例:** 「每一步都让用户确认」不是这招——女娲六站只停两次,停的位置是挑出来的;逢站必停是把判断成本转嫁给用户。
**在哪几个 skill 里见过:** nuwa-skill;庖丁的「先写小样验证格式再批量写作」是同构思路。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 长流水线、高返工成本 | 管用 | 拦截点的期望收益远大于暂停开销 |
| 用户不在场的定时批量任务 | 得让一步 | 人工点头改成机器检查或抽样后置审 |
| 三步小任务 | 没必要 | 直接跑完重看更便宜 |

**一起读:**
- A3 调研不落盘等于没做（前置：有落盘档案,检查点才有东西可验）
- A7 验收权交给外人和机器（区别于：中途对齐 vs 末端验收,两道闸各管一段）

### A9 模糊需求先诊断再开工 · 维度：需求

**症状:** 用户说「我想提升决策质量」。默认 agent 当场给了五条通用决策建议——用户真正想要的「帮我选一个思维教练」没人接住;另一个极端是连问五轮把用户问跑。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 把困惑当问题直接回答,或无上限追问 | 困惑先对「需求维度表」定位 → 最多追问 2 轮 → 推荐≤3 个候选,每个必须写明局限 |

**Therefore:** 入口先分流「目标」和「困惑」,困惑走专门的诊断路径,追问和推荐都设硬上限。

**机制原文:**

> 追问原则:
> - 最多问2轮,不要变成问卷调查
>
> 推荐原则:
> - 不超过3个候选,选择困难比没选择更糟
> - 必须说清楚局限——没有万能的思维框架

三条限流各防一个失败:问卷化、选择瘫痪、过度承诺。

**机制说明:** 诊断的定位工具是一张「需求维度表」(十种困惑 → 思维框架方向),把「凭感觉联想推荐」换成「查表定位」。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 工具型 skill 的输入天然分「点名式」和「症状式」两类时:选库、选方案、选人。
**什么时候太重:** 输入格式可控的内部流水线(上游永远给结构化输入),分流分支是死代码。
**反例:** 「先问清楚需求再动手」不是这招——要点是限流(2 轮、3 候选)和强制写局限;不限流的「问清楚」恰恰是它要防的问卷化。
**在哪几个 skill 里见过:** nuwa-skill。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 面向最终用户的咨询型入口 | 管用 | 症状式输入占一半,分流收益大 |
| 用户输入已经很明确 | 不用做 | 直接路径只确认不追问 |
| API 式结构化调用 | 用不上 | 输入形态已锁定,无需诊断 |

**一起读:**
- A6 60 分诚实优于 90 分编造（搭配用：诊断阶段就给冷门对象压预期,同一种「提前说」）

### A10 表达 DNA 量化+语气校准锚点 · 维度：品味

**症状:** 人设的内容对了,腔调全错:「作为一名企业家,我认为这个赛道值得理性看待。」——孙宇晨从不「理性看待」。通用 AI 那层礼貌中庸的底色,把人物声纹整个盖掉了。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 风格描述只有两个形容词:「自信、高调」 | 20 段抽样统计句式指纹(平均句长/疑问句比例/类比密度)+禁忌词表(「可以考虑」禁用,「All in」多用)+一句可自检的锚点 |

**Therefore:** 把「像他」拆成可执行的写作规则:统计出来的指纹、列成表的词汇边界、一句能当场自检的语气锚点。

**机制原文:**

> 从此人的长文/演讲中随机抽取20个段落,统计:平均句长、疑问句比例、类比密度、确定性语气比例……
>
> 校准标准:读完你的回复,如果感觉像「一个理性的人在分析孙宇晨的操作」,那就错了。应该感觉像「一个完全不觉得自己有任何问题的人在教你怎么赢」。

第一段是提炼期的量化方法(来自 extraction-framework),第二段是成品里的运行期锚点(来自孙宇晨成品)——量化定规则,锚点防漂移。

**机制说明:** extraction-framework 同时给了防过头的刹车:口癖「适度使用(太多变成模仿秀)」。品味规则两头都要拦:不像,和太像。
**解法层次:** 表征解法
**可迁移性:** 高
**什么时候用:** 任何「输出要带特定声音」的生成任务:品牌文案、人物代笔、翻译腔调。
**什么时候太重:** 输出本该中性的场景(技术文档、法务文本),声纹规则是噪音。
**反例:** 收集 50 句口头禅撒进回答不是这招——那是模仿秀;DNA 的主体是句式结构、节奏、确定性习惯这些「怎么说」,口癖只是佐料。
**在哪几个 skill 里见过:** nuwa-skill;它的主题 skill 变体明确「不模拟特定人物语气」,反向印证这套规则只该用在人物场景。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 表达极端的人物(孙宇晨) | 管用 | 声纹特征强,规则抓得准 |
| 表达平淡的学者 | 得让一步 | 指纹弱,辨识度更多靠思想内容立住 |
| 主题 skill | 用不上 | 刻意要求中性专业表达 |

**一起读:**
- A5 矛盾保留为张力（搭配用：声纹和张力共同构成「认得出是谁」）
- A7 验收权交给外人和机器（下游接管：100 字盲测验收这套规则的效果）

### A11 给人设装 Agentic Protocol · 维度：行为

**症状:** 静态人设被问「Solana 生态最近怎么样」,用训练语料里的过时 TVL 流畅作答——数字错了,腔调还很自信,使用者毫无察觉。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 收到问题直接进入角色开答 | 先分类:需要事实? → 强制 WebSearch 拿真数据 → 再用人物框架开口 |

**Therefore:** 「先做功课再发言」写进生成的 skill 本身;查什么,由这个人的心智模型推导,不写通用搜索步骤。

**机制原文:**

> 为什么需要这个段落:让人物不只是「说得像」,还「做得像」。没有这个段落,人物Skill遇到需要事实的问题时会凭训练语料编造,而不是像真人一样先做功课再发言。
>
> 关键约束:研究维度必须来自心智模型,不能是通用的「搜索相关信息」。

第一句点名症状;第二句防这招的退化形态——「必要时可搜索」等于没写。

**机制说明:** 这是给产物加器官,不是给流程加步骤:女娲流水线本身不变,变的是它生产的每个人物 skill 的解剖结构。所以已蒸馏的 13 个人物能批量补装(v3.0 一次性升级)。
**解法层次:** 表征解法
**可迁移性:** 高
**什么时候用:** 生成的 prompt/skill/agent 将来要回答事实类问题时。
**什么时候太重:** 纯虚构角色(小说人物)或离线环境——搜索步骤永远空转。
**反例:** 在人设里加一句「必要时可以搜索」不是这招——协议是强制分类+具体到数据项的研究清单(「查 TVL、日活地址、DEX 交易量」),模糊授权挡不住编造。
**在哪几个 skill 里见过:** nuwa-skill v3.0;是「先检索后回答」agent 模式的人格化变体。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 财经/科技人物(事实密集问题) | 管用 | 数据时效直接决定回答质量 |
| 哲学家人设(纯框架问题为主) | 可以松点 | 分类后大部分问题直接走框架,搜索少触发 |
| 离线/无网络环境 | 用不上 | 协议的研究步骤无法执行 |

**一起读:**
- A1 先取证再提炼,不许凭记忆写人设（对照：同一个「不许编」,A1 在生产期,A11 在运行期）

### A12 字幕获取交给脚本回退链 · 维度：平台

**症状:** agent 手动调 yt-dlp 抓访谈字幕:第一次语言代码不对,第二次拿到自动字幕的满屏时间戳,第三次连续重复行没去——三轮试错烧掉的上下文比字幕正文还长。（证据：结构推断）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| agent 现场试 yt-dlp 参数 | `download_subtitles.sh <URL>` 一条命令:人工中文→人工英文→自动生成三级回退;`srt_to_transcript.py` 去时间戳、去重、合段 |

**Therefore:** 平台怪癖(字幕语言、人工/自动之分、SRT 格式噪音)固化进脚本,agent 只负责调用。

**机制原文:**

> # 优先下载人工字幕,无人工字幕则下载自动生成字幕
> # 语言优先级:中文 > 英文 > 其他
>
> # 去重(自动字幕常有连续重复行)

「自动字幕常有连续重复行」这种注释只能来自真实踩坑——YouTube 自动字幕的滚动渲染会产生大量重复行,不去重的文本没法读。

**机制说明:** 两个脚本是一条链:下载管「拿到」,清洗管「能读」。产物写进 `sources/transcripts/`,供对话路和表达路两个调研 agent 用。
**解法层次:** 脚本解法
**可迁移性:** 低
**不可迁移原因:** 平台伤疤——整条回退链是给 yt-dlp 和 YouTube 字幕生态量身定做的;换 B站、小宇宙,参数和格式全要重写。能搬走的只有元原则「易错机械活下沉成脚本」,那是另一个层面的事。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| YouTube 长访谈取证 | 管用 | 回退链覆盖了绝大多数字幕形态 |
| B站/播客平台 | 用不上 | 脚本不支持,需另写 |
| 用户直接提供 transcript | 不用做 | 素材已是干净文本 |

**一起读:**
- A3 调研不落盘等于没做（搭配用：脚本产物按规矩落盘进 sources/）

## 残渣与砍掉候选

### quality_check.py 的正则检查
**判定:** 过度设计
**理由:** 思路(机器数硬指标)是对的,实现太脆:把它跑在源包自带的孙宇晨成品上,结果 5/6——「诚实边界 0 条」是误报,因为成品用数字列表(`1.`)而正则只数 `-`/`*` 开头的行;「一手来源占比」用关键词出现次数代替真实来源计数,直接跳过了检查。出厂示例跑不过出厂检查器(实测)。

### output/ 目录
**判定:** 过度设计
**理由:** 某次生成残留的 html/md/bak 文件被提交进仓库,与 skill 机制无关。skill 自己立了「自包含、可分发」的洁癖,这个目录违背它——砍掉候选。

### merge_research.py 的矛盾检测与占比统计
**判定:** 货物崇拜
**理由:** 把它跑在源包自带的孙宇晨示例上(实测):矛盾检测抓到的「矛盾点」是「争议(2018年1月爆发)**:」这类被关键词正则截下来的碎片——普通转折词全会误报,真正的语义级矛盾(言行不一)一个抓不到;「一手占比 73/150=48.7%」同样是关键词出现次数而非来源计数,而且按女娲自家「>50%」的通过线,出厂示例自己不过线。摘要表的来源 URL 计数部分有用,这两个子功能是装饰性的。

### skills-lock.json
**判定:** 平台伤疤
**理由:** skills.sh 分发平台的锁文件,与 skill 行为无关,换分发渠道即失效。

## 盲区

- 调研 agent 自己也是 LLM,同样会编造来源 URL——女娲要求每条信息标注来源,但没有任何 URL 可达性或真实性校验机制,假出处可以一路混到成品附录
- 已知测试的测试集污染:测试问题如果与调研素材重合,子 agent 带着 skill 答对只证明「复读得好」,不证明框架对新问题有泛化力;skill 没有要求测试问题避开调研语料
- 活人名誉与人格权风险没有系统机制:孙宇晨成品里的免责声明是该案例手工加的,SKILL.md 流程里没有「争议人物 → 强制免责声明」的规则,下一个争议人物可能就没有
- 生成 skill 的长度没有上限控制:孙宇晨成品 488 行,每次激活全量进上下文;蒸馏得越认真,运行时越贵,这笔账没人管
- 多语言人物的表达 DNA 分裂:调研档案明确发现孙宇晨中英文两套人设(「英文世界的 Crypto Statesman vs 中文世界的搞事 90 后」),但 skill-template.md 没有承接字段,写不写、怎么写全凭当次发挥
