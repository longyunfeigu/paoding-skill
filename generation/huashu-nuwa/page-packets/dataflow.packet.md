# dataflow.packet

**Page job:** 沿数据走:用户一句话 → sources/ → research/01-06.md → 两份检查点摘要 → SKILL.md → 测试/精炼报告。每个承重产物回答「为什么长这样」。
**Reader state:** 已知六站流程;现在想知道文件层面谁写谁读、形状为什么反直觉。
**Voice:** 教学口吻,产物卡为主,叙事为辅。
**Page-specific standard:** 每张产物卡必填「为什么长这样」(反直觉形状 vs 直觉形状的坏结果);glossary 收录的承重工件(research 档案、SKILL.md 成品)带标本:真实实例代码块+逐字段注释。
**Evidence shape:** data-flow SVG 主轴图;sun-yuchen research/03、06 摘录作标本;成品 SKILL.md 心智模型卡作标本。
**Failure mode:** 写成目录清单(「references/ 下有两个文件」),没有 ownership 和形状理由。
**Pain scan rows used:** P3, P4(落盘+自包含), P1(中间产物=心智模型而非语录), P2(三重验证决定 SKILL.md 模型区形状), P9(检查点摘要为何存在)。
**Inputs:** brief 中间产物清单(全量,一个不漏);data-flow 图;sun-yuchen 标本。
**Must include:** 开头一句话总任务+data-flow 图;产物卡:research/01-06(合并为一卡+分工表)、sources/、Phase1.5 摘要表、Phase2.5 提炼摘要、SKILL.md 成品、测试报告;每卡六字段;≥2 个标本。
**Must avoid:** 把所有 14 个产物各开一卡(次要的归入清单表);无「为什么长这样」的卡。
**Packet output:** `content/dataflow.md`。
**Self-check:** 每张卡都有「写错会坏什么」的可观察下游失败吗?标本注释是「字段编码了什么设计决策」而不是「字段是什么意思」吗?
