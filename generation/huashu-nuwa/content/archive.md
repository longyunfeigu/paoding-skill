## 卡片

### A1 金句不是 DNA · 维度：领域-认知

**症状:** 你问人设：「Vision Pro 现在值不值得做？」它答：「人们不知道自己想要什么，直到你把它放到他们面前。值得做。」——流畅、像他，但没查任何最新事实，是用旧语料编的，而且你看不出来。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 中间产物是语录集：50 条「Stay hungry」式金句 | 中间产物是判断系统：4 个心智模型，每个带应用方式和局限 |

**Therefore:** 把流水线的中间产物从「他说过什么」换成「他怎么想」。

**机制原文:**

> 女娲不是复制人，是提炼思维框架。……关键区分：捕捉的是 HOW they think，不是 WHAT they said。

**机制说明:** 这是表征层的决定：同样的调研材料，压缩目标不同，产物的泛化能力天差地别。语录只能复述，模型能推断新立场。
**解法层次:** 表征解法
**可迁移性:** 高
**什么时候用:** 任何「从材料中提炼可复用知识」的任务——拆解一个 skill、总结一个领域、做一个顾问。问自己：中间产物是表面特征还是生成机制？
**什么时候太重:** 用户就是要一个语录墙或表情包人设——娱乐场景里判断系统是过度工程。
**反例:** 把金句分类整理得再好（按主题/年份/场景），仍然是金句，不是模型。
**在哪几个 skill 里见过:** huashu-nuwa

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 思维顾问类人物 skill | 管用 | 核心价值就是对新问题的判断力 |
| 娱乐向角色扮演 | 用力过了 | 用户要的是味道，不是推理 |
| 历史人物教学 skill | 看情况 | 教思想史要模型，教生平金句也够 |

**一起读:**
- A2 三重验证筛模型（下游接管：定了「要模型」之后，靠它判断什么算模型）
- A6 矛盾是特征不是 bug（搭配用：模型之间的张力也是表征的一部分）

### A2 三重验证筛模型 · 维度：领域-认知

**症状:** 调研文件里有一句「Stay hungry, stay foolish」（2005 斯坦福演讲），默认 agent 把它写进核心思想第一条——可这句是他引用《全球概览》封底的话，连原创都不是。随口一说、场合引用和真信念，在单条材料里长得一模一样。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 「他说过专注很重要」→ 直接进心智模型 | 「专注」在产品、招聘、战略三个域复现 + 能推断新立场 + 别人不这么想 → 才进 |

**Therefore:** 给「什么算核心思想」定三条可执行的判据，不达标的降级而不是删除。

**机制原文:**

> 验证1: 跨域复现——出现在至少 2 个不同领域。验证2: 有生成力——可以推断此人对新问题的可能立场。验证3: 有排他性——不是所有聪明人都会这样想。……仅 1-2 重 → 降级为决策启发式；0 重 → 不纳入。

**机制说明:** 三条判据分别防三种假货：孤例、死知识、普通常识。降级通道让筛选不粗暴——过一两重的仍是有用的启发式。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何要从大量候选里挑「真正核心」的提炼任务。判据可换，结构不变：多重验证 + 降级通道。
**什么时候太重:** 候选本来就只有三五个，筛选仪式比直接判断还贵。
**反例:** 只数出现次数（出现 ≥3 次就算）——高频口癖会通过，那是表达 DNA 不是心智模型。
**在哪几个 skill 里见过:** huashu-nuwa

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 候选 15-30 个的人物提炼 | 管用 | 这正是它的设计场景 |
| 材料极少的冷门人物 | 得让一步 | 跨域复现凑不齐 2 个域，标注推测属性 |
| 提炼一个领域的方法论 | 看情况 | 排他性要改成「流派区分度」 |

**一起读:**
- A1 金句不是 DNA（前置：先定表征目标，再谈筛选标准）
- A6 矛盾是特征不是 bug（区别于：筛的是真假，矛盾处理的是真与真打架）

### A3 六维取证 · 维度：领域-认知

**症状:** 人设张口闭口「现实扭曲力场」「改变世界」——溯源发现调研产物前三条全出自同一篇 10w+ 文章。它学会了爆款文里的词，却不知道 1997 年他回归后砍掉 70% 产品线时是怎么做决策的。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 搜「乔布斯 思维方式」读前 10 条结果 | 六个 agent 分头取证：著作/对话/表达/他评/决策/时间线，各有提取重点 |

**Therefore:** 先设计「理解一个人需要哪几个观察面」，再让并行 agent 按面取证。

**机制原文:**

> | 2 对话 | 被追问时的回答方式、即兴类比、改变立场的瞬间、拒绝回答的问题 | | 5 决策 | 决策背景与逻辑、事后反思、言行一致/不一致案例 |

**机制说明:** 维度清单本身是被固化的方法论——「拒绝回答的问题」「言行不一致案例」这种提取重点，是作者对「怎么理解人」的认知，不是搜索技巧。并行只是执行手段。
**解法层次:** 表征解法
**可迁移性:** 高
**什么时候用:** 调研任何复杂对象（人、公司、技术栈）之前，先回答「理解它需要哪几个互相印证的观察面」。
**什么时候太重:** 对象简单或信息本来就少——六个 agent 翻一个只有十条公开信息的人，是仪式不是取证。
**反例:** 开六个 agent 搜同一个关键词的不同页码——并行了，但没有维度。
**在哪几个 skill 里见过:** huashu-nuwa

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 公众人物深度建模 | 管用 | 材料多且杂，维度防以偏概全 |
| 冷门人物 | 得让一步 | skill 自己降到 2-3 个模型 + 加大诚实边界 |
| 快速了解某人观点 | 没必要 | 读一篇靠谱长访谈就够 |

**一起读:**
- A4 不存文件的调研等于没做（搭配用：六路并行的产出必须各有住址）
- A9 信息源黑名单（搭配用：维度保广度，黑名单保纯度）

### A4 不存文件的调研等于没做 · 维度：编排

**症状:** 提炼时我想引用 Agent 2 找到的那段 1995 年访谈原话，翻遍上下文，只剩它当时汇报的一句「已完成对话维度调研，发现若干有价值观点」——原话、出处、上下文全没了。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 子 agent 把调研总结返回在消息里 | 子 agent 写入 references/research/02-conversations.md，消息只报告写了什么 |

**Therefore:** 并行任务开工前先钉死产物的文件名和位置，交接走文件不走上下文。

**机制原文:**

> 每个 subagent 必须把调研结果写入对应的 md 文件。不存文件的调研等于没做。

**机制说明:** 配套的目录结构在 Phase 0.5 就建好（先有住址再有居民），自包含约束保证整个目录复制即用。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何多 agent 并行产出、下游还要消费的编排——文件系统是最便宜的共享内存。
**什么时候太重:** 单 agent 一口气完成的小任务，落盘是纯开销。
**反例:** 让子 agent「记得保存重要发现」——没有钉死文件名的落盘要求等于没有要求。
**在哪几个 skill 里见过:** huashu-nuwa；book_skill 的每章独立 .typ 文件是同一招

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 多 agent 并行调研/写作 | 管用 | 交接和审计都靠它 |
| 单次问答任务 | 没必要 | 没有第二个消费者 |
| 产物是大二进制 | 看情况 | 住址原则不变，格式要换 |

**一起读:**
- A3 六维取证（前置：先有维度分工，才有六个住址）
- A5 便宜返工点检查点（下游接管：落了盘，检查点才有东西可检）

### A5 便宜返工点检查点 · 维度：行为

**症状:** Skill 交付，用户试了一句就回来：「这不像他，太鸡汤了。」回溯发现调研阶段搜到的就全是鸡汤文——400 行产物从地基起就是错的，整体重写。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 调研→提炼→构建→交付一口气跑完 | 调研后停一次（材料质量），提炼后停一次（方向），各等用户确认 |

**Therefore:** 把检查点放在「上游产物刚成形、下游昂贵工作未开始」的位置，并给用户结构化摘要而不是原始材料。

**机制原文:**

> 这个检查点的意义：调研质量决定了最终 Skill 的上限。垃圾进垃圾出，在这里拦截比在 Phase 4 返工成本低得多。

**机制说明:** 两个检查点位置不同分工不同：1.5 拦材料（来源数、矛盾点、不足维度），2.5 拦判断（模型对不对、缺不缺）。摘要由 merge_research.py 自动生成，降低用户的确认成本。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 流水线里存在「主观判断重 + 下游成本高」的环节时，在它前后各放一个。
**什么时候太重:** 全自动批处理场景——没有用户在场，检查点变成永久阻塞。
**反例:** 每一步都问用户「可以继续吗」——那是把责任推给用户，不是检查点设计。
**在哪几个 skill 里见过:** huashu-nuwa

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 交互式长流水线 | 管用 | 用户在场且返工贵 |
| 无人值守 cron 任务 | 反而碍事 | 没人确认，流程卡死 |
| 三步以内的短任务 | 没必要 | 返工本来就便宜 |

**一起读:**
- A4 不存文件的调研等于没做（前置：检查点检查的就是落盘产物）
- A8 子 agent 独立验证（对照：检查点靠用户把关，验证靠独立 agent 把关）

### A6 矛盾是特征不是 bug · 维度：领域-认知

**症状:** 材料里同时有「专注就是说不」（1997）和「我们要同时做平板、手机、音乐」（2010）。默认 agent 写成「他主张在专注与多元之间取得平衡」——圆滑得不属于任何活人。Phase 4 把「观点高度一致」明确列为不通过信号：太假。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 「他既说过 X 也说过非 X，综合来看他认为折中」 | 「早期说 X（1997 访谈），后期转向非 X（2010 决策），张力保留」 |

**Therefore:** 给矛盾建类型学（时间性/领域性/本质性），各有处理方式，禁止调和。

**机制原文:**

> 矛盾是人格的核心特征，不是需要修复的 Bug。……错误的处理方式：❌ 选一边忽略另一边 ❌ 编一个调和的解释 ❌ 假装矛盾不存在

**机制说明:** 配套两条硬规则：调研侧「发现矛盾时保留矛盾，不要和稀泥」；验证侧「内在张力至少 2 对」——矛盾太少不通过。
**解法层次:** 表征解法
**可迁移性:** 高
**什么时候用:** 提炼对象是真实的人、组织、思想体系——任何本身就含张力的东西。
**什么时候太重:** 提炼的是规范文档或标准流程——那里的矛盾真是 bug，该修。
**反例:** 罗列所有矛盾不分类——没有类型学的矛盾清单只是混乱，不是深度。
**在哪几个 skill 里见过:** huashu-nuwa

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 人物/思想建模 | 管用 | 张力是辨识度的来源 |
| 技术规范提炼 | 反而碍事 | 规范里的矛盾要消除不是保留 |
| 多流派主题 skill | 看情况 | 矛盾改叫流派分歧，处理方式类似 |

**一起读:**
- A2 三重验证筛模型（区别于：那边筛真假，这边处理真与真的冲突）
- A8 子 agent 独立验证（下游接管：「张力≥2 对」在验证站被机器检查）

### A7 60 分诚实大于 90 分编造 · 维度：品味

**症状:** 蒸馏一个只有 8 条公开信息的独立开发者，产物照样有七个心智模型——后五个是把《高效能人士的七个习惯》的通用道理换上了他的名字。看起来越完整，编造占比越高，越难发现。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 冷门人物照样产出 7 个模型的完整 skill | 模型减至 2-3 个、每个标注「基于有限信息推测」、诚实边界加大篇幅 |

**Therefore:** 把「诚实优先于完整」写成红线，并给信息不足定好降级动作。

**机制原文:**

> 宁可生成一个诚实标注了局限的 60 分 Skill，也不要生成一个看起来完美但实际上在编造的 90 分 Skill。

**机制说明:** 不是一句口号，有配套机制：诚实边界是模板必备 section；冷门人物有专门的降级流程；验证标准要求「至少 3 条具体局限」，只写「不能替代本人」不算。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何生成式交付——把「质量不够时的降级动作」预先定义好，agent 才有编造之外的出路。
**什么时候太重:** 几乎没有。这条的成本只是篇幅变短。
**反例:** 在末尾加一行「以上内容仅供参考」——免责声明不是诚实边界，具体说出哪个维度信息不足才是。
**在哪几个 skill 里见过:** huashu-nuwa；book_skill 的「付印前提醒人工通读」同源

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 信息稀疏的生成任务 | 管用 | 编造风险最高的地方 |
| 信息充足的常规任务 | 可以松点 | 降级动作很少触发 |
| 创意虚构写作 | 用不上 | 编造就是任务本身 |

**一起读:**
- A3 六维取证（前置：先尽力取证，谈不足才有底气）
- A5 便宜返工点检查点（搭配用：信息不足在 1.5 检查点就向用户摊牌）

### A8 子 agent 独立验证 · 维度：行为

**症状:** 主 agent 报告：「三项测试均通过，风格高度还原。」用户上手第一个问题就穿帮——出题、答题、阅卷是同一个上下文，它考的全是自己刚写过的内容。能发现的问题，生成时就不会犯。（证据：实测）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 主 agent 自查后报告「三项测试均通过」 | spawn 子 agent 带着新 skill 答三类题，主 agent 对比结果 |

**Therefore:** 验证者和生成者分离，测试题分三类各管一头（对方向、看分寸、防 AI 味）。

**机制原文:**

> 生成 Skill 后，用子 agent 执行 3 项测试（独立于主 agent，避免自评偏差）

**机制说明:** 边缘测试的期望输出设计得很讲究——正确答案是「基于模型 X 和 Y 的推断，可能……但不确定」，斩钉截铁反而不通过。这在测试「知道自己不知道」的能力。
2026-06 消融实测（小样本，N=1 生成者 + 2 独立评审）：同一份稀薄材料生成的人物 skill，生成者同上下文自检 6 PASS／0 FAIL；两个独立评审用同一张表一致给出 5 PASS／1 FAIL——漏掉的恰是承重项（心智模型应整体降级）。实验记录见 `ablation/`。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何 agent 生成、agent 验证的闭环——验证者必须是没参与生成的新上下文。
**什么时候太重:** 产物有机器可判的硬标准（编译、测试）时，先用机器，独立 agent 留给主观维度。
**反例:** 同一个 agent「换个角度再检查一遍」——上下文没换，偏差还在。
**在哪几个 skill 里见过:** huashu-nuwa；本手册自己的 voice gate 独立审阅是同一招

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 主观质量验证（像不像、好不好） | 管用 | 没有机器标准，只能拼独立性 |
| 有编译器/测试套件的产物 | 得让一步 | 机器先行，agent 补盲区 |
| token 预算极紧 | 看情况 | 独立验证翻倍成本，挑最贵的环节用 |

**一起读:**
- A5 便宜返工点检查点（对照：用户把关方向，独立 agent 把关质量）
- A6 矛盾是特征不是 bug（搭配用：「张力≥2」正是它检查的标准之一）

### A9 信息源黑名单 · 维度：平台

**症状:** research/03 里赫然出现「乔布斯临终遗言曝光：财富不过是习惯了的生活」——溯源是公众号转知乎转贴吧，三手之后已无原始出处，而这条伪语录正是中文搜索的高权重结果。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 搜索结果按相关度照单全收 | 知乎/公众号/百度系永远排除，中文只收权威媒体白名单 + 原始音视频 |

**Therefore:** 对失真率高的信息生态，用「永远排除」的黑名单 + 点名的白名单，不留自由裁量。

**机制原文:**

> 信息源黑名单（永远排除）：知乎：洗稿严重、信息失真率高，不作为任何维度的来源。微信公众号：封闭生态、无法验证……中文渠道只接受权威媒体：36氪、极客公园、晚点LatePost、财新……

**机制说明:** 注意它的不对称设计：英文世界没有黑名单，中文世界黑白名单都点到具体平台名——这是对特定信息生态的精确补丁。
**解法层次:** 流程解法
**可迁移性:** 低
**不可迁移原因:** 平台伤疤——名单本身只对 2026 年前后的中文信息生态成立，平台兴衰后名单就过期。可迁移的只有「按生态失真率分级管控来源」这个抽象结构，具体名单不能搬。

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 中文公众人物调研 | 管用 | 正是它的设计场景 |
| 英文人物调研 | 用不上 | skill 自己都没给英文设黑名单 |
| 三年后的中文调研 | 看情况 | 名单需要重新校准 |

**一起读:**
- A3 六维取证（搭配用：维度保广度，名单保纯度）

### A10 需求诊断反推对象 · 维度：需求

**症状:** 用户：「我总觉得自己做决定太慢，想来想去最后还是选错。」agent：「请问您想蒸馏哪位人物？」用户：「……我要是知道还问你干嘛。」对话当场冷掉。（证据：作者证词）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| 「请问你想蒸馏哪位人物？」 | 一轮追问定位场景 → 给 3 个带局限说明的候选 → 用户挑 |

**Therefore:** 把「需求 → 对象」的反推做成对照表 + 追问轮数上限 + 固定的候选展示格式。

**机制原文:**

> 追问原则：最多问 2 轮，不要变成问卷调查。……推荐原则：不超过 3 个候选，选择困难比没选择更糟。……必须说清楚局限——没有万能的思维框架。

**机制说明:** 十行需求维度表把开放问题变成查表；候选格式强制三栏（核心镜片/为什么适合你/局限），推荐自带反面。
2026-06 消融实测补注：3 个基线 agent 收到同款模糊需求，没有一个干瘪反问（基线比卡面场景强了），但 3/3 走向「造通用决策工具」、0/3 想到人物蒸馏——这张对照表的现代价值是把模糊需求路由进基线到不了的解法空间。见 `ablation/`。
**解法层次:** 流程解法
**可迁移性:** 高
**什么时候用:** 任何入口可能收到模糊需求的 skill——把「澄清」做成有上限的结构化流程，而不是开放式反问。
**什么时候太重:** 工具型 skill 的输入本来就是结构化参数，没有模糊空间。
**反例:** 连问五轮的「需求调研问卷」——澄清失控成审讯，违反它自己的轮数上限。
**在哪几个 skill 里见过:** huashu-nuwa

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 面向非专家的入口 | 管用 | 用户说不清需求是常态 |
| 专家用户 + 明确指令 | 不用做 | 直接路径已经覆盖 |
| 需求维度无法枚举的领域 | 得让一步 | 对照表退化成示例集 |

**一起读:**
- A7 60 分诚实大于 90 分编造（搭配用：候选必须写局限，是同一种诚实）

### A11 字幕管线脚本化 · 维度：领域-工程

**症状:** agent 手工下了自动字幕、没清洗就入库——频次统计第一名是时间戳箭头「-->」，而且滚动重复让每句话出现 2-3 次，恰好污染提炼标准里「反复出现 ≥3 次＝真信念」这条核心判据。分析废了，但表面看不出来。（证据：实测）

**最小对照:**

| 没有这个机制 | 有这个机制 |
| --- | --- |
| agent 自己摸索 yt-dlp 参数再手工清洗 | bash download_subtitles.sh <URL> → python3 srt_to_transcript.py，两步出干净文本 |

**Therefore:** 把易错且重复的素材处理做成开箱即用的脚本，agent 只负责调用。

**机制原文:**

> Step 1 下载字幕：bash [skill目录]/scripts/download_subtitles.sh——自动优先人工字幕 → 中文 → 英文 → 自动生成字幕。Step 2 清洗为纯文本：srt_to_transcript.py——去时间戳、序号、HTML标签、连续重复行。

**机制说明:** 四个脚本各管一段机械活：下载、清洗、调研统计（merge_research.py）、质量自检（quality_check.py）。「自动优先人工字幕」这种 fallback 顺序就是踩坑后固化的经验。
2026-06 消融实测：真实形态的滚动自动字幕直接入库，最高频 token 是「-->」（10 次）、HTML 标签混入、每句因滚动重复出现 2-3 次；经 `srt_to_transcript.py` 清洗后每句一次、无任何残留。记录见 `ablation/`。
**解法层次:** 脚本解法
**可迁移性:** 高
**什么时候用:** 流程里有「步骤固定、参数易错、重复执行」的环节——判断标准是你会不会想给 agent 写操作说明书，会就改成脚本。
**什么时候太重:** 只执行一次的探索性操作，写脚本比手工还贵。
**反例:** 把需要判断的活也塞进脚本（比如「自动挑选最有价值的访谈」）——脚本接管机械，不接管判断。
**在哪几个 skill 里见过:** huashu-nuwa；book_skill 的 chroma_key.py / build_book.py 同款思路

**力度对比:**

| 场景 | 效果 | 为什么 |
| --- | --- | --- |
| 高频重复的素材处理 | 管用 | 错误率和成本同时降 |
| 一次性探索操作 | 没必要 | 脚本化成本收不回 |
| 步骤需要临场判断 | 反而碍事 | 脚本会把判断写死 |

**一起读:**
- A3 六维取证（搭配用：脚本喂干净素材，agent 专心取证）

## 残渣与砍掉候选

### Phase 5 双 Agent 精炼的两个固定视角
**判定:** 平台伤疤
**理由:** Agent A/B 分别要求「auto-skill-optimizer 视角」「skill-creator 视角」——这是对作者本地 skill 生态的依赖。换一个没有这两个 skill 概念的环境，这段指令退化成普通的「再审一遍」。独立精炼这个动作有效（见 A8），但绑定具体外部 skill 名是本项目特有。

### 「品味守则（速查）」小节
**判定:** 过度设计
**理由:** 三条守则（长文>金句、争议>共识、变化>固定）的内容已经分散体现在六维提取重点和三重验证里，速查表与 Phase 4 通过标准表也大面积重叠。去掉后行为应当不变——未实测，置信度中等。

## 盲区

- 同名人物歧义没有处理指引：「蒸馏张伟」会发生什么，skill 没有写。
- 信息源黑名单靠 agent 自觉遵守，调研产物没有机器校验来源合规的环节（quality_check.py 只查最终 SKILL.md）。
- 蒸馏在世人物的争议立场（政治表态、诉讼中的指控）可能带来名誉风险，skill 没有任何处理指引。
- 「为什么是这六个维度」缺少作者解释——少一维会怎样、能不能换一维，无从验证。
