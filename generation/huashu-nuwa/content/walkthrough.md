## stage-01 入口分流与需求澄清

**kicker:** Phase 0 / 0A / 0B
**summary:** 先判断用户给的是明确人名还是模糊需求，两条路走法完全不同。
**面包屑:** 【分流澄清】 → 建目录 → 六维取证 → 调研检查点 → 提炼 → 构建验证

### 场景再现

我收到的全部输入是这一句：

```text
帮我做一个乔布斯 skill，用来审视产品设计和战略取舍。
```

这是个明确人名，走直接路径。但同样常见的输入是另一种：

```text
我总觉得自己做决定太慢，想来想去最后还是选错。
```

这种输入里没有任何人名。我要交出的东西是一样的：确认过的蒸馏对象 + 用途 + 语料情况。

### 难点
**领域难点:** 确无
**行为难点:** 实测了 3 个不带女娲的基线 agent：没有一个干瘪反问（它们把需求拆解得有模有样），但 3/3 走向「给你造一个通用决策教练工具」，0/3 想到「有人已经把这个问题想透了——去蒸馏他」。默认 agent 到不了这个解法空间，而且用户不知道自己错过了什么。（证据：实测）

### 预测点

用户只说「想提升决策质量」，没说要谁。如果是你写规则，你会让 agent 怎么把这句话变成一个具体的蒸馏对象？先想好你的方案。

### 机制与产出

skill 把模糊路径做成了一张「需求维度 → 思维框架方向」的对照表，并且管住了追问的节奏：

> 追问原则：
> - 最多问 2 轮，不要变成问卷调查
> - 如果用户已经表达得足够清晰，不追问，直接推荐
> - 追问的目的是区分相似维度（比如「决策」是商业决策还是人生决策？）

推荐时还强制带上局限——「必须说清楚局限——没有万能的思维框架」。这一站结束时我手里有：

```text
对象：乔布斯 ／ 用途：思维顾问（聚焦产品与战略） ／ 语料：无本地素材，走网络搜索
```

### 收尾
**可偷的招:** 当入口可能收到说不清的需求时 → 把澄清做成「需求维度对照表 + 追问轮数上限」，不要开放式反问。
**对应档案:** A10
**下一步靠这个:** 对象和用途定了，建目录时才知道目录该叫什么、调研该聚焦哪个方向。

### 阶段速查
**这一步收到什么:** 用户一句话（人名或模糊需求）
**我不能直接做什么:** 不能跳过确认直接开始调研
**我产出什么:** 确认过的对象 + 用途 + 语料模式
**自由度:** limited

## stage-02 先建目录，给调研钉住址

**kicker:** Phase 0.5
**summary:** 调研还没开始，先把空目录建好——每份调研结果都有固定住址。
**面包屑:** 分流澄清 → 【建目录】 → 六维取证 → 调研检查点 → 提炼 → 构建验证
**接上一步:** 对象和用途已确认，可以放心创建以它命名的目录了。

### 场景再现

我还没搜任何资料，先执行的是建目录：

```text
.claude/skills/steve-jobs-perspective/
├── SKILL.md                  # 最终产物（现在是空的）
├── scripts/
└── references/
    ├── research/             # 01-writings.md ... 06-timeline.md
    └── sources/              # books/ transcripts/ articles/
```

### 难点
**领域难点:** 确无
**行为难点:** 并行子 agent 的调研结果如果只活在各自的对话上下文里，汇总时就只剩印象——引用不出任何一条具体来源。（证据：作者证词）

### 预测点

六个并行 agent 马上要出发了。你会用什么办法保证它们的成果三天后还找得到、而且别的阶段能直接用？

### 机制与产出

skill 把这条规则写成了死命令，原文只有一句话但份量很重：

> 每个 subagent 必须把调研结果写入对应的 md 文件。不存文件的调研等于没做。

还有一条配套的自包含约束：

> 所有调研文件必须存在 skill 目录内部（`references/research/`）……Skill 必须是自包含的——复制整个 skill 目录就能独立使用，不依赖任何外部文件。这是为开源分发设计的核心原则。

这一站的产出就是那个空目录本身——六个文件名已经钉死，后面谁写哪个文件没有任何发挥空间。

### 收尾
**可偷的招:** 当多个并行 agent 的产出要被下游消费时 → 开工前先钉死产物的文件名和位置，先有住址再有居民。
**对应档案:** A4
**下一步靠这个:** 六个 agent 各自知道往哪写，提炼阶段知道去哪读。

### 阶段速查
**这一步收到什么:** 确认过的对象与用途
**我做什么:** 创建目录骨架，检查更新模式/本地语料
**我产出什么:** 带固定文件名的空目录
**自由度:** almost-none

## stage-03 六维并行取证

**kicker:** Phase 1
**summary:** 六个并行子 agent 分头翻著作、对话、表达、他评、决策、时间线。
**面包屑:** 分流澄清 → 建目录 → 【六维取证】 → 调研检查点 → 提炼 → 构建验证
**接上一步:** 住址钉好了，六个 agent 可以同时出发。

### 场景再现

我现在要 spawn 六个子 agent。给 Agent 1（著作）的任务原文是这样的：

```text
你的任务：调研乔布斯的著作和系统性长文。
搜索方向：
- 反复出现≥3次的核心论点（这些是真信念）
- 自创术语和概念
输出要求：
- 写入 [skill目录]/references/research/01-writings.md
- 每条信息标注来源URL和可信度
- 区分一手（此人写的）vs 二手（别人总结的）
信息源黑名单：不使用知乎、微信公众号、百度百科。
```

### 难点
**领域难点:** 只看一种来源，理解出来的人是漫画。一篇爆款文章里的乔布斯和决策记录里的乔布斯不是同一个人——理解一个人本身就需要取证维度的设计。（证据：作者证词）
**行为难点:** 默认 agent 搜中文资料会大量命中洗稿文和二手转述，调研文件看着厚实，全是失真信息。（证据：作者证词）

### 预测点

如果让你设计「理解一个人」的调研分工，你会切成哪几块？切完对一下女娲的六维，看看你漏了哪个、它漏了哪个。

### 机制与产出

六维分工每一维都有明确的「提取重点」，不是泛泛的「搜索相关信息」：

> | 1 著作 | 反复出现的核心论点（≥3次=真信念）、自创术语、推荐书单 |
> | 2 对话 | 被追问时的回答方式、即兴类比、改变立场的瞬间、拒绝回答的问题 |
> | 5 决策 | 决策背景与逻辑、事后反思、言行一致/不一致案例 |

来源质量有一张权重表（一手素材最高、二手转述最低），中文渠道有一条不留余地的黑名单：

> 信息源黑名单（永远排除）：知乎：洗稿严重、信息失真率高……微信公众号：封闭生态、无法验证……百度百科/百度知道：信息陈旧且不可靠。

机械活全部交给脚本：字幕用 `download_subtitles.sh` 下载、`srt_to_transcript.py` 清洗（去时间戳、序号、重复行）。信息源不足时不硬撑：

> 宁可生成一个诚实标注了局限的 60 分 Skill，也不要生成一个看起来完美但实际上在编造的 90 分 Skill。

产出是六份各自归位的调研文件：

```text
references/research/01-writings.md      （8 篇来源）
references/research/02-conversations.md （5 段长访谈）
...
references/research/06-timeline.md      （含最近 12 个月动态）
```

### 收尾
**可偷的招:** 当你要让并行 agent 调研一个复杂对象时 → 任务书里写「提取重点」而不是「搜索主题」，配上来源权重表和黑名单。
**对应档案:** A3
**下一步靠这个:** 检查点要拿这六份文件算账：来源够不够、矛盾在哪。

### 阶段速查
**这一步收到什么:** 空目录 + 对象与聚焦方向
**skill 让我读什么:** 六维分工表、信息源权重与黑名单
**我不能直接做什么:** 不能用黑名单来源，不能不落盘
**我产出什么:** research/01-06.md 六份调研文件
**机制线索:** 固定住址线：建目录 → 写文件 → 提炼只读文件
**自由度:** limited

## stage-04 调研检查点

**kicker:** Phase 1.5
**summary:** 全部 agent 完成后暂停，把调研质量摘要拍给用户看。
**面包屑:** 分流澄清 → 建目录 → 六维取证 → 【调研检查点】 → 提炼 → 构建验证
**接上一步:** 六份调研文件就位，但先别急着提炼。

### 场景再现

我跑 `merge_research.py` 自动统计六份文件，然后把这张表展示给用户：

```text
│ Agent            │ 来源数量  │ 关键发现                  │
│ 1 著作           │ 8篇      │ 核心论点: 现实扭曲力场... │
│ 3 表达           │ 120条    │ 高频词: "insanely great" │
│ 矛盾点           │ 2处      │ Agent1说X, Agent4说Y     │
│ 信息不足维度      │ 无       │                          │
```

### 难点
**领域难点:** 确无
**行为难点:** 默认 agent 拿到材料就闷头往下跑，方向错误要到交付时才暴露，返工成本最大。（证据：作者证词）

### 预测点

检查点放在哪最划算？调研后？提炼后？构建后？女娲放了两个，先想想你会放在哪、为什么。

### 机制与产出

skill 自己把这个检查点的存在理由说得很清楚：

> 这个检查点的意义：调研质量决定了最终 Skill 的上限。垃圾进垃圾出，在这里拦截比在 Phase 4 返工成本低得多。

用户确认 OK 才进提炼；觉得某维度不够，就补充调研再继续。产出是一个被用户盖过章的调研基线。

### 收尾
**可偷的招:** 当流水线里有「主观判断重、下游返工贵」的接缝时 → 把检查点钉在接缝上，给用户结构化摘要而不是原始材料。
**对应档案:** A5
**下一步靠这个:** 提炼拿到的是用户确认过质量的材料，不用边提炼边怀疑地基。

### 阶段速查
**这一步收到什么:** 六份调研文件
**我做什么:** 跑 merge_research.py，展示摘要，等用户确认
**我产出什么:** 用户确认过的调研基线
**自由度:** almost-none

## stage-05 三重验证提炼

**kicker:** Phase 2 / 2.5
**summary:** 把 15-30 个候选论点筛成 3-7 个心智模型，宁少勿多。
**面包屑:** 分流澄清 → 建目录 → 六维取证 → 调研检查点 → 【提炼】 → 构建验证
**接上一步:** 调研质量用户已确认，现在开始整条流水线主观判断最重的一站。

### 场景再现

我逐个读 `01-writings.md` 到 `05-decisions.md`，列出乔布斯所有反复出现的论点，得到 20 多个候选：

```text
候选 01  现实扭曲力场            （出现于: 02-conversations, 04-external-views）
候选 02  专注就是说不            （出现于: 01-writings, 02, 05-decisions）
候选 03  技术与人文路口          （出现于: 01, 02）
候选 04  不做市场调研            （出现于: 02, 05）
候选 05  舞台演讲穿黑色高领      （出现于: 03-expression-dna）
...
```

第一秒的本能是把最醒目的几条直接包装成心智模型。skill 不让。

### 难点
**领域难点:** 两层。第一层：随口一说和真信念长得一模一样，不筛就会把场合话写成核心思想。第二层：就算筛对了，如果产出形态是语录集，遇到新问题照样没有生成力——这正是开场那个「编 Vision Pro 答案」的根。（证据：作者证词）
**行为难点:** 默认 agent 提炼时会把矛盾的材料调和成一个圆滑的版本，产出「观点高度一致（太假）」的人设。（证据：作者证词）

### 预测点

「专注就是说不」和「舞台演讲穿黑色高领」都是乔布斯反复出现的特征。你用什么标准判断哪个该进心智模型、哪个只是表面特征？写下你的筛法。

### 机制与产出

每个候选要过三道筛，原文在 extraction-framework.md：

> 验证1: 跨域复现——同一个思维框架出现在此人讨论的至少 2 个不同领域。
> 验证2: 有生成力——用这个模型可以推断此人对新问题的可能立场。
> 验证3: 有排他性——不是所有聪明人都会这样想。

三重全过才算心智模型；只过一两重降级为决策启发式；全不过丢弃。矛盾不调和，有专门的处理框架：

> 矛盾是人格的核心特征，不是需要修复的 Bug。……错误的处理方式：❌ 选一边忽略另一边 ❌ 编一个调和的解释 ❌ 假装矛盾不存在

提炼完成后是第二个检查点（Phase 2.5），把「心智模型 N 个、启发式 N 条、核心张力 N 对」的摘要再给用户确认一次。产出长这样：

```text
心智模型（4个）: 现实扭曲力场 / 专注即拒绝 / 技术×人文 / 端到端控制
决策启发式（7条）: 「如果要做市场调研，就已经输了」...
核心张力（2对）: 极简主义 vs 完美主义的无限打磨
诚实边界: 不能预测他对 AI 时代的立场；信息截止 2026-06
```

### 收尾
**可偷的招:** 当你要从一堆候选里挑「真正核心」时 → 定多重验证判据 + 降级通道——不达标的不是删掉，是降级。
**对应档案:** A2
**下一步靠这个:** 构建阶段只做组装，所有判断在这一站已经做完并被确认。

### 阶段速查
**这一步收到什么:** 六份确认过的调研文件
**skill 让我读什么:** extraction-framework.md 的三重验证与矛盾处理
**我不能直接做什么:** 不能把金句直接包装成模型，不能调和矛盾
**我产出什么:** 心智模型/启发式/表达DNA/张力/诚实边界 + 用户确认
**机制线索:** 检查点节奏线：1.5 拦材料 → 2.5 拦方向 → 4 拦质量
**自由度:** creative

## stage-06 构建、独立验证、精炼

**kicker:** Phase 3 / 4 / 5
**summary:** 按模板组装 SKILL.md，spawn 子 agent 独立测试，最后双 Agent 精炼。
**面包屑:** 分流澄清 → 建目录 → 六维取证 → 调研检查点 → 提炼 → 【构建验证】
**接上一步:** 提炼结果用户已确认，组装不再有方向风险。

### 场景再现

我读 `skill-template.md`，把提炼结果逐 section 填进去。最特别的一段是「回答工作流（Agentic Protocol）」——它要求我根据乔布斯的心智模型，反推他分析问题时会查什么：

```text
乔布斯式研究维度（从心智模型推导）：
- 看产品：上手体验的前 30 秒？哪里能砍掉一半功能？
- 看战略：这件事是不是处在技术与人文的路口？
- 看人：团队里谁是 A player？
```

### 难点
**领域难点:** 人设「说得像」不等于「做得像」——没有回答工作流，skill 遇到事实问题还是会编。研究维度还必须因人而异，芒格查激励结构、塔勒布查尾部风险，通用的「搜索相关信息」等于没有。（证据：作者证词）
**行为难点:** 主 agent 检查自己的产物，分数必然偏高——能发现的问题在生成时就不会犯。消融实测：生成者自检 6/0 全过，两个独立评审一致 5/1，漏的正是承重项。（证据：实测）

### 预测点

你怎么测一个人物 skill 像不像？想出三个测法，再对照女娲的三项测试。

### 机制与产出

验证由独立的子 agent 执行，原文点明了原因：

> 生成 Skill 后，用子 agent 执行 3 项测试（独立于主 agent，避免自评偏差）

三项测试各管一头：已知测试对答案（拿他公开表态过的问题对方向）、边缘测试看分寸（没讨论过的问题，期望「基于模型 X 的推断，可能……但不确定」而不是斩钉截铁）、风格测试防 AI 味。通过标准是张可机检的表（quality_check.py 自动跑），其中最反直觉的一条是：

> | 内在张力 | 至少 2 对矛盾 | 观点高度一致（太假） |

矛盾太少反而不通过。迭代有上限（Phase 2→4 最多循环 2 次），到顶就在诚实边界里标注薄弱维度交付，不无限打磨。最后 Phase 5 双 Agent 精炼，展示验证结果给用户确认后交付。

### 收尾
**可偷的招:** 当产物的质量只能主观判断时 → 验证交给没参与生成的子 agent，并把「不通过信号」写成与通过标准并列的一列。
**对应档案:** A8
**练习:**

- 「内在张力至少 2 对」这条标准，对政治人物 skill 会不会反而危险？
- 迭代上限 2 次是拍脑袋还是有依据？你的项目里这个数该怎么定？
- Agentic Protocol 的研究维度从心智模型推导——如果某人的模型全是抽象哲学，推不出可搜索的维度怎么办？

### 阶段速查
**这一步收到什么:** 确认过的提炼结果 + skill-template.md
**我不能直接做什么:** 不能自己验证自己，不能无限迭代
**我产出什么:** 通过验证的 steve-jobs-perspective/SKILL.md
**下一步谁用它:** 最终用户激活使用
**自由度:** limited
