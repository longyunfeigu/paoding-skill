## 产物卡

### references/research/01-06.md
**谁写它:** stage-03 的六个并行子 agent，一人一份，文件名在 stage-02 就钉死了
**谁读它:** stage-04 的 merge_research.py 统计来源；stage-05 提炼时逐份扫描；stage-06 汇总进「调研来源」section
**它管什么:** 原始证据——谁说的、在哪说的、可信度几级、一手还是二手、矛盾原样保留
**它不管什么:** 结论。这六份文件里不许出现「所以他的心智模型是……」
**为什么长这样:** 直觉做法是边搜边总结，一步到位。拆成「证据文件 → 提炼」两层，是因为提炼是主观判断最重的环节——判断必须能被审计。用户在检查点质疑某个模型时，能翻回证据文件看它是从哪几条材料推出来的；证据和判断混在一起，错了连错在哪一层都查不出来。
**写错会坏什么:** 二手洗稿文混进来没标可信度，下游三重验证拿着失真材料照样三重通过，整个 skill 建立在假证据上。

### sources/（books / transcripts / articles）
**谁写它:** 用户提供的一手素材直接放入；字幕脚本下载清洗后存入 transcripts/
**谁读它:** 六个调研 agent 按维度分类消化（一本书可能同时覆盖著作和表达两个维度）
**它管什么:** 未经任何转述的一手原文
**它不管什么:** 任何分析和摘要
**为什么长这样:** 信息源权重表里「用户提供的一手素材」排最高一档。给一手素材单独的物理住址，是为了让「一手」和「二手」的边界在文件系统层面就分开，而不是靠调研文件里的一个标注。复制整个目录时，证据链跟着走。
**写错会坏什么:** 一手二手混放，来源权重表失去抓手，「一手来源占比 >50%」这条通过标准没法算。

### references/skill-template.md
**谁写它:** 女娲的作者，随包分发，运行时只读
**谁读它:** stage-06 构建时逐 section 填充
**它管什么:** 目标 skill 的结构契约——frontmatter、角色扮演规则、心智模型、表达 DNA、诚实边界、每个 section 的格式和顺序
**它不管什么:** 内容本身。模板里没有任何乔布斯
**为什么长这样:** 直觉做法是让 agent「参考之前的例子写一个」。模板把结构从生成里抽出来，意味着 15 个 examples 里的人物 skill 结构完全一致——用户学会用一个就会用全部，质检脚本也才有固定的锚点可查。
**写错会坏什么:** 模板缺一个 section（比如诚实边界），所有后续生成的人物 skill 集体缺这个 section，quality_check.py 全部报错。

### steve-jobs-perspective/SKILL.md
**谁写它:** stage-06 组装，stage-04～05 的两次用户确认决定了它的内容
**谁读它:** 最终用户的 agent 激活使用；「更新模式」下女娲自己重读它做增量更新
**它管什么:** 可运行的判断系统——心智模型、决策启发式、表达 DNA、回答工作流、诚实边界
**它不管什么:** 证据细节（住在 research/）和一手原文（住在 sources/）
**为什么长这样:** 它不是文档，是程序。「回答工作流」一段让它面对新问题时先查再答；「诚实边界」一段让它知道自己不知道什么。一个会引用语录的文件是数据，一个知道何时犹豫的文件才是判断系统——这是整条流水线对任务本质的回答。
**写错会坏什么:** 缺了回答工作流，skill 退化回开场那个凭旧记忆编 Vision Pro 答案的默认 AI——整条流水线白跑。
